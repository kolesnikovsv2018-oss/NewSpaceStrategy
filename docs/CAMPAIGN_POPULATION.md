# Население кампании — Н06

Согласованный и реализованный контракт от 2026-10-24.
[Модель](../src/domain/campaignPopulation.ts) не зависит от Phaser.
Демография действует только в Conquest; мирная песочница не изменена.

## Правила и точность

- Одна хранимая единица — 1000 жителей; UI показывает миллионы.
- Дом начинает с 5000 единиц (5 млн), новая колония — с 1000 (1 млн).
- Пригодный тип: базовая вместимость 10000, абсолютная 20000 единиц.
  `K = min(base + доступные улучшения, absolute)`; биосфера даёт+2000.
  Для barren оба предела0,
  колонизация запрещена.
- Запись `{population, remainder}` существует для каждого пригодного мира,
  включая нейтральный с нулём; для barren записей нет. Владение хранится только
  в `session.galaxy.systems`, отдельного demographic owner нет.
- `population` — целое0..1e9, `remainder` —0..<100 с точностью0,01. P выше K/абсолютного
  предела структурно разрешено для будущего изменения среды; автоматической убыли нет.

На успешный собственный конец хода при `0 < P < K`:

Без технологий сохраняется прежняя формула ниже. Н09 применяет
относительный бонус биологии2%→2,4% с целочисленным числителем
в базисных пунктах и сохранением дробного остатка; полный
[контракт](CAMPAIGN_COLONY_TECHNOLOGIES.md).

```text
numerator = P * 2 + remainder
delta = min(K - P, floor(numerator / 100))
Pnext = P + delta
remainderNext = Pnext == K ? 0 : numerator % 100
```

При P=0, P=K или P>K прирост0, запись/остаток не меняются.
Для P=1 рост на единицу произойдёт на50-м собственном конце хода, без
бесплатного минимального прироста. При P=9999 прирост ограничен одной единицей.
Причины прогноза: `growing`, `empty`, `at-capacity`, `over-capacity`.

## Основание и захват

После [Д08](CAMPAIGN_TRAVEL.md) основание только явным `colonize` с shipId
стоящего колонизатора, расходуемого при успехе:

1. Выбрать собственную колонию с P≥2000, отличную от цели.
2. Минимальное расстояние — евклидово по исходным координатам; равенство решается
   ASCII ID источника, независимо от порядка массивов.
3. Списать20 кредитов/10 минералов и1000 единиц населения источника.
   Его остаток сохраняется; цель получает `{population:1000,remainder:0}`.

Ручной отказ `NO_SETTLERS`/`INSUFFICIENT_RESOURCES` атомарен.
Автоматического основания и его notices больше нет.
Несколько оснований последовательно используют уже изменённые казну/источники.
Наличие корабля/наблюдения, пригодность и отсутствие врагов проверяет Conquest.

Захват населённой колонии не является основанием: сохраняются100% населения
и остатка, платы/переноса нет. Прежняя очередь удаляется без refund.

## Время, проекция и сохранение

Н07 рассчитывает бюджет по исходным населению и назначениям:
валовой доход `3 credits/1 mineral` на единицу P и содержание
`1 credit/P + 1 credit/корабль`. Session применяет бюджет и own arrivals;
затем Conquest применяет промышленный FIFO и научный/культурный выпуск по
исходному P, рост исходно собственных колоний, research, mining,
encounters/захват, validation/outcome.
Выпуск не зависит от прироста текущего хода; ownership до encounters остаётся исходным.
Захваченный мир не получает дополнительный рост в этой транзакции.
Явно основанная колония существует до следующего own-end и растёт на нём.
Чужой конец хода не развивает колонию, даже если encounters меняют её владельца.
Поздний отказ, включая overflow бюджета/добычи или ошибку боя, откатывает весь
кандидат вместе с выпуском и ростом.

Own-view содержит только свои P/K/delta/reason/next и quotes наблюдаемых
нейтральных миров; полные rules и чужие демографические записи туда не входят.
UI не вычисляет демографию повторно. AI использует эту же проекцию, основывает
только при успешном quote; при равных ближайших маршрутах распределяет цели
по рангу собственных ship IDs, без скрытой памяти противника.

Н10 добавил [runtime-среду/survey/адаптацию](CAMPAIGN_PLANETOLOGY.md).
Growth/capacity читают текущий тип; toxic K6000/absolute12000,
с biosphere8000. Оккупация без адаптации не обнуляет жителей.

Единственный актуальный военный save12/rules9 требует `environment`/`surveys`, `population`,
`colonyOutput`, `researchJournal` и `rules` (snapshot7/rules7, таблицы `campaign-tables-v4`,
policies `population-v1` и `colony-output-v1`).
K/forecast/notices не сериализуются. Иные версии/неполные данные отвергаются,
без миграции и fallback. `rules.treeId` совпадает с деревом партии;
Н09 допускает только связанные с исследуемыми узлами колониальные effects.
`CURRENT_GAME_RULES_CONSUMERS` включает colony-technologies-v1,
не применение библиотечных примеров `ship-growth` или policy-reference.

Н07 заменил военный доход10/5 на расчёт по населению; мирная экономика
и мирный FIFO не изменились. Миграция между действующими колониями, еда,
и терраформирование не реализованы. Рост и вместимость Н09 используют S0;
завершённая в этой транзакции технология применяется со следующего own-end.
