## Назначение и повторение

### Сравнение развития по готовому архиву

Для ограниченного сравнения двух политик на одной оплаченной истории:

```sh
yarn baseline:conquest --development --archive <case.run.json.gz> --output-dir <new-dir> --from-window 160
```

Это отдельный диагностический режим, не новая настройка игры.
Он читает полный large cutoff200 и соседний `*.result.json`, проверяет
SHA256/входы/актуальные версии, воспроизводит старые принятые команды
через настоящий executor и сверяет полный finalState.
Затем из строгого save после160 окон запускает текущую policy только
до исходных200. Ни turn/counters, ни прежний результат cutoff не сбрасываются.

Проверяются repeat, initial round-trip, midway save/непустое продолжение
и повтор записанных новых команд. При слишком коротком суффиксе midway
помечается unavailable, а не passed. Ошибка архива/версии/исполнения
отклоняется явно; результат не «чинится».
Метрики различают idle industry assignments, заполнение бюджета,
реальные основания/изучения и смены владельцев. Полное состояние
разрешено только диагностическому наблюдателю, не planner.
Отсутствие новой территории или заполнение24 само по себе не доказывает цикл.

Артефакты: `summary.json`, `windows.json.gz`, `before.save.json`,
`current.save.json` и при наличии точки `midway.save.json`.
Каталог должен быть новым, его родитель — существующим; записи с `wx`.
Новая политика действует **только после старого префикса**: такое
сравнение нельзя выдавать за свежую большую партию от начального состояния.
После изменения форматов нужен новый совместимый архив, не миграция
исторического Д15-результата.

### Полная исходная матрица

Это диагностика нынешнего Conquest, не публичный режим «все AI» и не гарантия
баланса. Н06 подключил демографию, Н07 — назначения/выпуск и резервы очков.
Runner находится в
[src/diagnostics/conquestBaseline.ts](../src/diagnostics/conquestBaseline.ts).
Он использует существующие `planConquestAction`, `executeConquestAction` и настоящий
тактический resolver; Phaser и тестовые fixtures не импортируются.

```sh
yarn baseline:conquest --output ./baseline-new.json
```

Файл должен быть новым, каталог — существующим. Запись UTF-8 с `wx` не заменяет
существующий файл. Неверные аргументы, ошибки IO/воспроизводимости и отказы executor
дают ненулевой exit code. Стратегический timeout — нормальный результат измерения.
Запуск использует существующий Vite SSR loader для TypeScript с extensionless
импортами, закрывает его после завершения; сервер игры и браузер не нужны.
Node/Yarn — те же, что у приложения. Дополнительных зависимостей нет.

## Утверждённые входы

До измерения пользователь утвердил:

| Параметр | Значения |
| --- | --- |
| Миры | 6, 40, 256 |
| Пары mapSeed / campaignSeed | 41 / 101; 12345 / 67890; 98765 / 43210 |
| Старт первого lineup | blue / red, прямой / зеркальный |
| Диагностические расписания первого lineup | current-ai, research-first, production-first |
| Второй lineup | current-ai |
| Обычные партии | 54; до 200 стратегических окон сторон |
| Boundary | 4; до 8 окон сторон |

Счётчик начинается с turn1/blue. Зеркало меняет дома участников и владельцев
домов в **той же** проверенной карте; координаты и нейтральные миры не меняются. В Д08 линий нет.
Первый lineup переносится с blue на red; первый действующий игрок по-прежнему blue.
Map seed не становится seed боя: отдельный campaign seed передаётся существующему
resolver, который выводит свои боевые потоки из seed/turn/battle ID/faction/ship ID.
Общие seed не гарантируют ничью или тождественные случайные потоки после смены сторон.
Canonical map snapshot сохраняется полностью, а не восстанавливается только по seed.

Все обычные ветви начинаются с настоящего `createConquest`, без флота/очереди,
со штатными 100 кредитами / 50 минералами. Доход, исследование, FIFO, deploy,
перелёты, ремонт, снабжение, захват и победа происходят только через настоящие команды.

Расписания — законные диагностические ограничения команд, не настройки нынешнего AI:

- `current-ai`: существующий planner, до 24 команд/окно, последняя принудительно endTurn;
- `research-first`: первый lineup не заказывает корабли до завершения всего дерева
  исследований; остальные команды прежние;
- `production-first`: пока нет собственных заказов/выпуска/кораблей и начатого
  либо завершённого исследования, первый lineup копит ресурс
  без исследования и покупает самый дешёвый доступный AI-проект
  (кредиты, затем ASCII ID); при наличии собственных записей — прежний planner.
  Условие читается из текущего сохраняемого state, не из скрытой истории runner.
  Это не «продвинутая производственная стратегия»; преимущество дешёвого первого
  проекта не доказывает универсального превосходства корпуса.

Boundary отделены полем `kind`:

- `symmetric-boundary`: по одному одинаковому вооружённому fighter в нейтральном
  пригодном мире; все исследования завершены диагностически;
- `supply-boundary`: по 100 одинаковых corvette в том же мире, только снарядное
  оружие, operational ammo0/fuel0, казны0/0, исследования завершены. Полное
  содержание учитывается до боя. Это искусственный дефицит, не оплаченная партия.

Оба boundary запускают только endTurn, а не попытки AI выбрать снабжение.
Безоружность по текущему боекомплекту приводит к настоящему тактическому timeout.
Это проверяет границу, но не означает, что обычный AI достиг такого состояния.

## Opt-in трасса окон Д13

```sh
timeout 1800s yarn baseline:conquest --trace-timeouts --output-dir ./d13-new
```

Это отдельная выборка18 paid6 до200 окон, а не полный58-run.
Каталог должен быть новым; существующий не перезаписывается. После каждой
партии сохраняются gzip JSON-трасса и полный текущий save после60 окон.
Д14 обрабатывает более короткие партии: если60 достигнуто уже после/при
остановке, сохраняется префикс после `min(60, turnsExecuted - 1)` окон.
Точка находится строго до остановки, проверяемый суффикс не пустой.
При отсутствии даже одного такого полного окна — явный отказ проверки,
а не успешный late oracle с пустым продолжением.
Итоговый `summary.json` появляется только после всех18 проверок:
обычный повтор без трассы, ранний checkpoint4 и поздний checkpoint
с фактическим номером в `verification.checkpointAt`.
Для позднего сравниваются все оставшиеся команды, статус, outcome,
полный finalState и сама пооконная трасса. Ошибки прекращают запуск
с ненулевым кодом; частичный каталог не является принятой матрицей.

Инструментальные форматы `orion-conquest-window-trace` и
`orion-conquest-timeout-analysis` имеют schemaVersion1 отдельно от
baseline12 и игровых форматов. Сводка содержит HEAD, SHA-256 всех
runtime-исходников/lockfile и агрегированный fingerprint: один HEAD
не описывает незакоммиченные Д12/Д13.

Третий аргумент `runBaseline` — доверенная диагностика с `onWindow` и
необязательным `checkpointAt` в пределах1..maxTurns. Без него сохраняется
прежняя форма результата и трасса не строится. Callback вызывается
только для принятого пакета; исключение observer не скрывается. Передаются
отделённые команды/поля, а не ссылки на Conquest. Каждая запись содержит
смены владельцев, новые отчёты боёв без frames, HP/ammo/fuel/transit,
проектные capabilities/боевые параметры, own knowledge обеих сторон,
науку, бюджет, FIFO/deploy и назначения/население. Отсутствующая запись
населения начального barren обозначена `null`, не вымышленным нулём.

Граница runner остаётся200 окон/24 команды на пакет. CLI держит трассу
одной партии и её продолжения, не всю18-матрицу с полными состояниями;
полный Conquest не копируется после каждой команды. Полный save строится
только в запрошенной точке, штатной ранней точке и для финального hash.
Это доверенная диагностика полного состояния, не новая own-view для AI/UI.
Регрессии изоляции, границ, rollback, ошибок и nullable population —
[conquestBaselineTrace.test.ts](../tests/conquestBaselineTrace.test.ts).
Каждое принятое ongoing-окно обязано продвинуть turn ровно на1.
Нулевое продвижение допустимо только для завершившей кампанию команды
до endTurn. Нарушение инварианта явно прерывает диагностику: callback/
executor с ошибочным success не может вызвать бесконечный внешний while.

## Формат и смысл метрик

Выход `orion-conquest-baseline`, schemaVersion12 содержит `summary`, `verification`,
`runs`. Каждая запись сохраняет входы, версии baseline12/save16/rules13/tree10/battlePolicy/tacticalRules,
карту, lineup→faction, полный finalState, журнал команд, промежуточный текущий save
и метрики. `productionPoints`, `researchPoints` и `culturePoints` — фактически произведённые
за наблюдавшиеся собственные ходы очки, а не остатки после расходов.
Н08 добавил researchSpent/researchOverflow/researchReserve/researchProgress:
научный расход, потери избытка, текущий резерв и незавершённый прогресс.
Checkpoint берётся на четвёртом окне вместо десятого, чтобы короткие партии
проверяли настоящий частичный science progress. `population` содержит фактические конечные
total/capacity по стороне.

Milestones по каждой стороне: первый запуск/завершение исследования,
новая колония (основание **или захват**, включая победу защитника),
заказ, выпуск в completed, deploy и встреча. Turn — окно **команды события**;
при встрече одна дата принадлежит обоим участникам. Дом и boundary-grants
не считаются первым заработанным событием.

- `measured`: событие действительно произошло, указан turn;
- `timeout`: событие не наблюдалось до конечного лимита, `throughTurn` — цензурирование;
- `unavailable`: не наблюдалось до иной остановки, не ноль.

Отдельные `status` completed/timeout/executor-error не смешиваются с tactical
`battleTimeouts`. Завершение считается только штатной победой all-planets;
лимит200 никогда не присуждает победу. Distribution даёт n/min/median/max только
наблюдаемых событий; censored/unavailable указаны отдельно. Два зеркала одного seed
не являются независимыми статистическими наблюдениями. Выборка3 seed-пары не
обосновывает CI универсального AI-баланса.

Выпуск ресурсов измеряется по квитанции принятого endTurn. Доход равен
3 credits и 1 mineral на единицу исходного населения собственных колоний;
содержание — 1 credit на единицу населения и корабль, оплачивается не более
доступных после дохода кредитов. Minerals delta включает реальную добычу после
arrivals; прогноз до прибытия не выдаётся за фактическую добычу. Очки выпуска берутся из receipt, а milestones заказа/release/deploy различают постановку,
завершение очереди и размещение.
`spent` хранит реальные дельты принятой команды и upkeep. После Д08
автооснования нет; его прежняя метрика founding остаётся нулевой.
Явное основание входит в `spent.colonize`. `released` —
новые записи completed, `losses` — погибших участников соответствующей стороны.
При будущей смене экономики необходимо одновременно обновить эти наблюдатели
и независимые oracles, а не переносить старые коэффициенты в новую модель.

`endTurnObservations` — видимые ограничения: активное исследование/FIFO, transit,
пустое топливо/боекомплект, дефицит содержания, отсутствие доступного по цене
AI-проекта, нулевое назначение промышленности, намеренная задержка производства.
Это **сосуществующие наблюдения**,
не доказательство причинности конкретной ветви planner и не взаимоисключающие
причины; сумма счётчиков может превышать число окон. Завершение расписания
помечено `no-further-command-in-diagnostic-schedule`.

Командный отказ сохраняет настоящий message и машинный `executorCode` executor,
без синтетического кода из русского текста. Н05а добавил типизированные отказы;
baseline8 сохраняет этот контракт и environment/surveys/rules/population/output/research/journal save12.
Терминальный colonize завершает пакет без endTurn: в turnsExecuted считаются
только действительно завершённые окна, сама команда остаётся в журнале.
Вместимость считается общим own query с технологическими K, не старой константой.
Предыдущие команды текущего диагностического пакета помечаются
rolled-back; finalState и метрики остаются на последнем принятом окне. Retry нет.

## Проверки

Каждый CLI-вход дополнительно исполняется заново: сравниваются полный state,
все команды и все метрики. Checkpoint после min(4, limit) принятых окон
кодируется/декодируется текущим save, после чего сравниваются весь командный
суффикс (включая следующий ход), статус и полный finalState.
Если игра остановилась раньше checkpoint, это явно `no-checkpoint-before-stop`.
Continuation API возвращает **метрики суффикса**, а не выдаёт их за накопленные
метрики полной партии; исходный JSON сохраняет полный непрерывный прогон.

```sh
yarn test tests/conquestBaseline.test.ts tests/conquestAi.test.ts tests/galaxyCampaign.test.ts
yarn typecheck
yarn build
```

Базовые данные и принятые после измерений контрольные диапазоны —
в [отчёте Н03](../reports/2026-10-10/07-n03-baseline-metrics.md).
Это headless integration/диагностика, не browser E2E, FPS или wall-clock benchmark.

Н07 заново измерил18 шестимировых вариантов с repeat/checkpoint:
