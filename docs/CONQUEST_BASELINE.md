# Контрольная матрица Conquest — Н03

## Назначение и повторение

Это диагностика нынешнего Conquest, не публичный режим «все AI», не новый баланс
и не реализация будущей науки/населения. Runner находится в
[src/diagnostics/conquestBaseline.ts](../src/diagnostics/conquestBaseline.ts).
Он использует существующие `planConquestAction`, `executeConquestAction` и настоящий
тактический resolver; Phaser и тестовые fixtures не импортируются.

```sh
yarn baseline:conquest --output ./baseline-new.json
```

Файл должен быть новым, каталог — существующим. Запись UTF-8 с `wx` не заменяет
существующий файл. Неверные аргументы, ошибки IO/воспроизводимости и отказы executor
дают ненулевой exit code. Стратегический timeout — нормальный результат измерения.
Запуск использует существующий Vite SSR loader для TypeScript с extensionless
импортами, закрывает его после завершения; сервер игры и браузер не нужны.
Node/Yarn — те же, что у приложения. Дополнительных зависимостей нет.

## Утверждённые входы

До измерения пользователь утвердил:

| Параметр | Значения |
| --- | --- |
| Миры | 6, 40, 256 |
| Пары mapSeed / campaignSeed | 41 / 101; 12345 / 67890; 98765 / 43210 |
| Старт первого lineup | blue / red, прямой / зеркальный |
| Диагностические расписания первого lineup | current-ai, research-first, production-first |
| Второй lineup | current-ai |
| Обычные партии | 54; до 200 стратегических окон сторон |
| Boundary | 4; до 8 окон сторон |

Счётчик начинается с turn1/blue. Зеркало меняет дома участников и владельцев
домов в **той же** проверенной карте; координаты, нейтральные миры и линии не меняются.
Первый lineup переносится с blue на red; первый действующий игрок по-прежнему blue.
Map seed не становится seed боя: отдельный campaign seed передаётся существующему
resolver, который выводит свои боевые потоки из seed/turn/battle ID/faction/ship ID.
Общие seed не гарантируют ничью или тождественные случайные потоки после смены сторон.
Canonical map snapshot сохраняется полностью, а не восстанавливается только по seed.

Все обычные ветви начинаются с настоящего `createConquest`, без флота/очереди,
со штатными 100 кредитами / 50 минералами. Доход, исследование, FIFO, deploy,
перелёты, ремонт, снабжение, захват и победа происходят только через настоящие команды.

Расписания — законные диагностические ограничения команд, не настройки нынешнего AI:

- `current-ai`: существующий planner, до 24 команд/окно, последняя принудительно endTurn;
- `research-first`: первый lineup не заказывает корабли до завершения всех трёх
  исследований; остальные команды прежние;
- `production-first`: пока нет собственных заказов/выпуска/кораблей и начатого
  либо завершённого исследования, первый lineup копит ресурс
  без исследования и покупает самый дешёвый доступный AI-проект
  (кредиты, затем ASCII ID); при наличии собственных записей — прежний planner.
  Условие читается из текущего сохраняемого state, не из скрытой истории runner.
  Это не «продвинутая производственная стратегия»; преимущество дешёвого первого
  проекта не доказывает универсального превосходства корпуса.

Boundary отделены полем `kind`:

- `symmetric-boundary`: по одному одинаковому вооружённому fighter в нейтральном
  пригодном мире; все исследования завершены диагностически;
- `supply-boundary`: по 100 одинаковых corvette в том же мире, только снарядное
  оружие, operational ammo0/fuel0, казны0/0, исследования завершены. Полное
  содержание учитывается до боя. Это искусственный дефицит, не оплаченная партия.

Оба boundary запускают только endTurn, а не попытки AI выбрать снабжение.
Безоружность по текущему боекомплекту приводит к настоящему тактическому timeout.
Это проверяет границу, но не означает, что обычный AI достиг такого состояния.

## Формат и смысл метрик

Выход `orion-conquest-baseline`, schemaVersion1 содержит `summary`, `verification`,
`runs`. Каждая запись сохраняет входы, версии baseline/save5/rules3/tree2/battlePolicy,
карту, lineup→faction, полный finalState, журнал команд, промежуточный текущий save
и метрики. Отсутствующие science points/population помечены
`mechanic-not-implemented`, а не числом0.

Milestones по каждой стороне: первый запуск/завершение исследования,
новая колония (основание **или захват**, включая победу защитника),
заказ, выпуск в completed, deploy и встреча. Turn — окно **команды события**;
при встрече одна дата принадлежит обоим участникам. Дом и boundary-grants
не считаются первым заработанным событием.

- `measured`: событие действительно произошло, указан turn;
- `timeout`: событие не наблюдалось до конечного лимита, `throughTurn` — цензурирование;
- `unavailable`: не наблюдалось до иной остановки, не ноль.

Отдельные `status` completed/timeout/executor-error не смешиваются с tactical
`battleTimeouts`. Завершение считается только штатной победой all-planets;
лимит200 никогда не присуждает победу. Distribution даёт n/min/median/max только
наблюдаемых событий; censored/unavailable указаны отдельно. Два зеркала одного seed
не являются независимыми статистическими наблюдениями. Выборка3 seed-пары не
обосновывает CI универсального AI-баланса.

Выпуск ресурсов измеряется по принятому изменению казны endTurn с добавлением
фактически оплаченного содержания. В нынешних правилах credits income =
10 × исходные собственные колонии, содержание =
min(исходная казна + income, исходные own ships). Minerals delta включает реальную
добычу после arrivals; прогноз до прибытия не выдаётся за фактическую добычу.
`spent` хранит реальные дельты по виду принятой команды и upkeep, `released` —
новые записи completed, `losses` — погибших участников соответствующей стороны.
При будущей смене экономики необходимо одновременно обновить эти наблюдатели
и независимые oracles, а не переносить старые коэффициенты в новую модель.

`endTurnObservations` — видимые ограничения: активное исследование/FIFO, transit,
пустое топливо/боекомплект, дефицит содержания, отсутствие доступного по цене
AI-проекта, намеренная задержка производства. Это **сосуществующие наблюдения**,
не доказательство причинности конкретной ветви planner и не взаимоисключающие
причины; сумма счётчиков может превышать число окон. Завершение расписания
помечено `no-further-command-in-diagnostic-schedule`.

Командный отказ сохраняет настоящий message executor. Нынешний executor не даёт
стабильного кода: `executorCode.status=unavailable`, без синтетического кода из
русского текста. Предыдущие команды текущего диагностического пакета помечаются
rolled-back; finalState и метрики остаются на последнем принятом окне. Retry нет.

## Проверки

Каждый CLI-вход дополнительно исполняется заново: сравниваются полный state,
все команды и все метрики. Checkpoint после min(10, limit) принятых окон
кодируется/декодируется текущим save, после чего сравниваются весь командный
суффикс (включая следующий ход), статус и полный finalState.
Если игра остановилась раньше checkpoint, это явно `no-checkpoint-before-stop`.
Continuation API возвращает **метрики суффикса**, а не выдаёт их за накопленные
метрики полной партии; исходный JSON сохраняет полный непрерывный прогон.

```sh
yarn test tests/conquestBaseline.test.ts tests/conquestAi.test.ts tests/galaxyCampaign.test.ts
yarn typecheck
yarn build
```

Базовые данные и принятые после измерений контрольные диапазоны —
в [отчёте Н03](../reports/2026-10-10/07-n03-baseline-metrics.md).
Это headless integration/диагностика, не browser E2E, FPS или wall-clock benchmark.
