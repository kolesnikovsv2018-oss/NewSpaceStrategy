# Н01 — время, единицы и атомарное завершение хода

**Дата:** 2026-10-10. **Статус:** согласованная доменная спецификация, документальная поставка Н01.
Порядок добычи, содержания, захвата, отложенных эффектов и полного раунда подтверждён пользователем.
Новый pipeline **не внедрён**. Население, очковая наука, культура, runtime-среда и договоры по-прежнему отсутствуют.

Основания: [задание Н01](../plans/tasks-2026-10-09/n01-time-contract.md),
[общий контракт](../plans/tasks-2026-10-09/00-execution-contract.md),
[план](../plans/plan-2026-10-09.md), [действующий Conquest](CAMPAIGN_CONQUEST.md).
Здесь фиксируется порядок и семантика, а не числовой баланс будущих механик или новые номера schemas.

## 1. Две шкалы времени

| Понятие | Единица и граница | Правило |
| --- | --- | --- |
| Стратегический ход стороны | Окно приказов, завершаемое одним успешным `endTurn` | Развитие этой стороны начисляется ровно один раз; бесплатные/оплаченные приказы внутри окна сами его не начисляют |
| Номер `turn` | Номер окна стороны, сейчас целое 1..1 000 000 000 | Успех `endTurn` даёт +1, отказ оставляет прежний номер; это не число раундов или боевых тактов |
| Собственный ход (`own-turn`) | Одно успешное завершение окна конкретной стороны | Единица роста, выпуска и стратегического движения; чужой `endTurn` не продвигает её развитие |
| Полный стратегический раунд | По одному успешному `endTurn` каждого участника расписания раунда | Сроки общих договоров и сравнительные метрики; повторного развития в конце раунда нет |
| Боевой такт | 0,05 секунды симуляции | Фиксированный шаг, не стратегический ход |
| Секунда боя | 20 боевых тактов | Максимум одного боя сейчас 120 секунд / 2400 шагов, независимо от wall-clock |
| Кадр отображения | Кадр RAF/Phaser или кадр записанного replay | Не начисляет развитие, не меняет уже принятые потери кампании |

Текущее расписание: нечётный `turn` — blue, чётный — red. Полный текущий раунд — окна 1/2, 3/4 и далее; отдельного persisted round-счётчика нет. Завершение кампании в середине пары не требует искусственного хода второй стороны.

Для Н17 чётность **не является контрактом**: расписание должно явно определять участника и границу раунда. Для будущих договоров резервируется один tick при закрытии полного раунда по закреплённому списку участников; отказ/повтор старой команды не закрывает раунд. Изменение состава расписания требует отдельной политики Н17, сроки и начало действия договоров — Н16. Не вводить эти поля или tick в Н01.

Тактический resolver может выполнить 0/1/несколько боёв внутри одной стратегической транзакции. Завершение боя, timeout, пауза, закрытие replay и его скорость не являются `endTurn`. [BattleScene](../src/scenes/BattleScene.ts) ускоряет накопитель fixed-step, но не меняет размер шага; [ConquestScene](../src/scenes/ConquestScene.ts) показывает уже рассчитанные кадры последнего боя со скоростью 8× и паузой, не запускает resolver повторно.

| --- | --- | --- |

| Производственный выпуск | production points/own-turn; прогресс — production points | Н07; нынешний FIFO измерен оставшимися собственными ходами, не очками |
| Научный выпуск | research points/own-turn; прогресс — research points | Н08; сейчас активная технология получает +1 progress за свой конец хода при колонии, порог в own-turn |

| Галактическая дистанция | Гал. ед.; скорость — гал. ед./own-turn | Н14 вводит длины линий; сейчас линия — пара ID без длины, координаты карты не тариф/дальность |
| Стратегическое топливо | Единица бака; сейчас расход 1/линию, ёмкость 3 | Не ЭЕ; сейчас прибытие за один собственный `endTurn`, независимо от тактической скорости |
| Тактическое расстояние/скорость | Такт. ед.; такт. ед./секунду симуляции | Координаты/дальность боя; не гал. ед. и не pixels отображения |
| Тяга | Условная единица тяги модели | Параметр формулы скорости с массой; не заявлять ньютоны или стратегический двигатель |
| Энергия / энергия выстрела | ЭЕ | Запас батареи и цена действия; не мощность |
| Генерация/потребление/мощность | ЭЕ/секунду симуляции | Не ЭЕ/own-turn; номинальный резерв мощности службы не второе списание стратегической батареи |
| Корпус/щит, боекомплект | HP, единица щита, число снарядов | Только корпус и ammo сейчас переносятся между боями; не население/минералы |
| Кадровое время | Миллисекунды реального времени | UI и накопитель; не persisted стратегический таймер |

[flightEstimate](../src/domain/flightEstimate.ts) оценивает непрерывное тактическое движение по энергии/чистой мощности/скорости. Даже результат `sustained` не означает бесконечного стратегического топлива, проходимости галактического маршрута или готовности к бою. Связь единиц/targets и округление эффектов — предмет [Н04](../plans/tasks-2026-10-09/n04-effects-rules.md); Н01 не вводит формул роста или конверсии points.

## 3. Фактический путь действующего `endTurn`

Прослежены [conquest.ts](../src/domain/conquest.ts), [campaignSession.ts](../src/domain/campaignSession.ts),
[campaignUpkeep.ts](../src/domain/campaignUpkeep.ts), [campaignResearch.ts](../src/domain/campaignResearch.ts)
и [conquestBattle.ts](../src/domain/conquestBattle.ts). Это описание текущего кода, не новый pipeline.

| № | Фактическая операция | Какие данные читает / меняет |
| --- | --- | --- |
| 1 | Полный strict parse Conquest и команды; expectedTurn → активная сторона → controller → completed → ссылки карты | Parse даёт независимое состояние; нарушение возвращает отказ без состояния |
| 2 | Session повторно проверяет session/команду; проверяет MAX_TURN и экономику | Исходные колонии действующей стороны и все её размещённые корабли, включая transit/группы |
| 3 | Валовой доход → проверка cap → содержание | 10 credits/5 minerals с каждой исходной своей колонии. Платёж `min(credits после дохода, число кораблей)`, недоплата не долг и не потеря |
| 4 | Продвижение производства | На свой ход один head FIFO каждой своей колонии; без spillover, новые completed не размещаются автоматически |
| 5 | Прибытия групп, затем собственных кораблей; `turn += 1` | Группа читает прежний маршрут участников; ship меняет systemId и удаляет transit. Чужие маршруты не продвигаются, топливо не возвращается |
| 6 | Исследование действовавшей стороны | +1 активному progress при хотя бы одной колонии до захватов; достигнут порог → completed, active=null |
| 7 | Добыча действовавшей стороны и проверка казны | После прибытия, до боя: с каждого корабля в barren `floor(min(10, сумма miningSpeed × efficiency))` minerals |
| 8 | Обход всех систем в каноническом порядке карты, а не только мест действовавшей стороны | Стоящие обе стороны → настоящий resolver; transit исключены. Встреча может состоять только из ранее стоявших кораблей |
| 9 | Результат каждого боя | Следующий battle ID/seed от seed партии, завершённого номера окна и ID боя; отчёт, HP/ammo survivors, удаление погибших/operations, фильтрация membership, группы <2 удаляются |
| 10 | Захват после боя или без боя | В пригодной системе одна стоящая сторона и хотя бы один вооружённый проект → её ownership/knowledge. Orders/completed другой стороны в системе удаляются без refund |
| 11 | Reveal обеих сторон, полный итоговый parse, возврат результата | Начальная карта не меняется. Scene принимает успешный state один раз; query вычисляет outcome из итогового владения |

Управляющая сторона экономики — faction команды, не победитель боя. На blue-end красный корабль может захватить мир в другой системе; это не начисляет red развитие. Доход прежнему владельцу на ходе захвата поступает **только если он завершает свой ход**; чужая сторона не получает доход автоматически при потере колонии.

Session создаёт `endTurnEconomy` для исходного завершённого окна, но Conquest сейчас не передаёт эту квитанцию наружу: `ConquestResult` содержит `state` и optional `frames`, либо `message`. Machine-readable коды полной Conquest-границы тоже пока отсутствуют. Н01 фиксирует требование будущего API, а не объявляет его реализованным.

`getConquestView` добавляет добычу к session forecast тем же `miningYield`: для own transit берёт destination, поскольку действующий маршрут прибывает за один own-turn. Это прогноз дохода/содержания/добычи, **не полный oracle боёв**. Он не гарантирует успешность команды при исчерпанном battle ID или иных поздних ошибках и не показывает будущую очередь/науку. Чужой forecast — условный собственный расчёт наблюдателя, не право команды.

Текущий resolver переносит HP/ammo, сбрасывает щит/энергию/cooldown на каждый новый бой; damage последовательный. Timeout с двумя оставшимися сторонами сохраняет потери и не даёт захвата. Следующий `endTurn` может разрешить новую встречу с новым ID. Последние 12 отчётов сохраняются, кадры только последнего рассчитанного боя возвращаются для replay и не входят в save.

## 4. Согласованный проектный pipeline

Обозначения: **S0** — проверенный снимок в момент команды после всех уже принятых приказов окна; **C** — независимый кандидат; **D** — единожды рассчитанный пакет развития действующей стороны. Это логические роли, не новые поля сохранения.

| Фаза | Читает | Результат / владелец начисления | Отказ, отменяющий всю команду |
| --- | --- | --- | --- |
| A. Проверка | Полный input, strict payload, расписание, controller, исходный outcome | Проверки в прежнем приоритете: state → command → stale → active/controller → completed → доменные условия/MAX_TURN | Неверная форма/версия/ссылка, stale, нет права, completed, предел окна |
| B. Фиксация | S0: свои колонии/население/труд, казны, флот, очереди, активные проекты, уже завершённые эффекты и runtime-среда | Один снимок выпуска и один набор получателей; S0 неизменен | Неверное распределение, отсутствующий обязательный handler или snapshot правил |
| C. Расчёт | Только S0 | D: доход/содержание, production/research/culture points, рост, прогресс проектов; только действующая сторона. Нет выпуска из только что выросшего населения | Нечисловой результат, несовместимая единица, cap, невозможный обязательный расход |
| D. Применение развития | C, рассчитанный D | Казна, прогресс/рост/очереди изменяются один раз. Нехватка содержания остаётся мягкой по текущей policy до явно согласованной замены | Несогласованный пакет, overflow; поздний расход не спасает уже превышенный валовой cap |
| E. Завершение открытий/среды | Прогресс после D, условия из S0 | Технологии/проекты переходят в completed, runtime-среда получает завершённое изменение. Новый экономический эффект действует только на следующий own-end | Недопустимое завершение/среда; не искать второй проект для рекурсивного расхода новых очков |
| F. Стратегическое движение | Маршруты и оснащение закреплённых кораблей C | Продвижение только действующей стороны; сейчас один шаг завершает маршрут, Н14 отдельно задаёт metric policy | Неверный endpoint, маршрут/топливо/согласованность membership; не читать тактический flight estimate |
| G. Добыча | Корабли после F; оплаченный design; среда, зафиксированная в S0 | Добыча действующей стороны до любых боёв. Прибывший добытчик успевает добыть, даже если погибнет ниже. Новая среда не меняет добычу в этой же транзакции | Overflow казны/некорректный yield; добыча не пересчитывает D |
| H. Встречи и потери | Стоящие корабли C, их operations, закреплённый оплаченный design, явные seed/policy | Канонический порядок систем; resolver → потери/HP/ammo → cleanup групп. Бои обеих сторон, без второго развития/содержания | Предел ID/невалидный результат/операции/refinement; timeout сам по себе не ошибка |
| I. Владение | Survivors после H в каждой системе | Захват и удаление orders/completed прежнего владельца без refund. Новый владелец получает развитие колонии только на следующем своём endTurn | Несогласованное владение/ссылки/очереди. Нет второго дохода, науки, роста или project tick |
| J. Завершение | Итоговый C | Видимость/knowledge, следующий участник и номер окна, при полном раунде один общий treaty tick без развития; outcome → полная итоговая schema → одна публикация C/квитанции | Любое позднее нарушение/cap отменяет и D, и перелёты, и бои, и владение, и round tick |

Внутри H/I разрешено последовательное применение потерь/захвата по системам, но наружу нет промежуточных состояний. Outcome кампании проверяется по полному результату всех встреч, а не останавливает обход на первой потенциальной победе. Перестановка владельцев не изменяет состав S0/D.

Нынешний session увеличивает номер до боя; в новом контракте это логически часть J. Во всех случаях отчёт/seed/квитанция относятся к **завершённому исходному окну**, не к следующему `turn`. Расположение вычисления в коде не должно менять эту семантику.

### Отложенные эффекты и автономное оснащение

- Экономический modifier завершённой технологии, новая вместимость/среда и новые работники не перерассчитывают текущий D. Следующий прогноз строится по итоговому C с уже завершёнными эффектами.
- Открытие capability может разрешить новый приказ в следующем доступном окне; оно не меняет ранее оплаченные design в orders/completed/ships.
- Бой не читает новый глобальный бонус для старого корабля: только закреплённое оснащение/operations и принятая policy. Переоснащение — отдельный оплаченный путь Н12.
- Технология, разблокированная prerequisites в E, не начинает и не завершает следующее исследование автоматически. Перенос остатка очков/округления требуют явного решения Н08, без рекурсивного выпуска.
- Граница экономической активации относится к концу хода начисления, не к replay, save/load или wall-clock.

### Нулевая колонизация, захват, пределы и completed

Без колоний выпуск/рост колоний нулевые, исследование приостановлено; оставшийся флот может двигаться, добывать и сражаться, его содержание считается. Нет автоматического поражения/дохода/лечения/долга. До Н18 сохраняется победа за все изначально пригодные миры снимка; изменение среды Н10/Н11 само знаменатель не меняет.

Корабль, уничтоженный в H, платит содержание в D по исходному флоту; новый completed из производства не платит до явного deploy. Погибший добытчик сохраняет уже начисленную в G добычу. Колония, захваченная в I, не получает развитие новому владельцу в D, даже если он действует; при захвате его же кораблями на чужом endTurn дохода прежнему владельцу также нет.

Старая очередь принадлежит старому владельцу: удаляются и queued, и completed, включая завершённый ранее в D заказ; его прогресс/готовность не передаются и не возмещаются. Счётчики ID не откатываются на меньшие значения после удаления; отказ всей транзакции, напротив, сохраняет исходные счётчики.

MAX_TURN блокирует `endTurn` до развития/перелётов. Он не запрещает все остальные разрешённые приказы автоматически, не завершает цель и не лечит корабль. Исчерпание battle ID при необходимой встрече — поздняя ошибка всей команды. Timeout боя — допустимый результат с реальными повреждениями, не победа/ничья кампании.

Completed проверяется до разрешения новых игровых команд и после полного успешного candidate; явная колонизация может закончить кампанию без `endTurn`. После completed запрещены игровые команды/AI, доступны просмотр/save/load/new/menu/takeover по прежнему контракту. Переключение controller не начисляет развитие. Финальная неудачная проверка не должна публиковать временный completed.

## 5. Прогноз, квитанция, IO и публикация

**Будущая граница:** типизированный отказ `code/message`, без state/частичной квитанции; успех содержит detached итог и квитанцию завершённого окна. Конкретные schemas/версии выбираются в реализующем этапе, Н01 не меняет Conquest save5/rules3 или tree2.

Прогноз и команда используют один pure расчёт D по S0, а не независимые UI-формулы. Прогноз содержит свою казну/выпуск/содержание/прогресс и известные причины отказа; не скрытый флот/прогноз боёв противника. Условность неактивного own-прогноза отмечается явно. Ошибка показывается вместо нулевых «успешных» чисел. Добыча отделена от исходного колониального выпуска и учитывает планируемые own arrivals, не повторный tick развития.

Квитанция фиксирует сторону и исходный номер окна, фактически начисленный выпуск/добычу/платёж/недоплату, продвижение и завершения, итоговую own-казну; боевые сведения только по правилам own-view. Успешная квитанция и следующий forecast различаются: первый относится к S0/D, второй к C. Дефицит содержания и timeout допустимы, overflow — нет. Квитанция/forecast/UI pages не сериализуются как второе состояние.

Scene публикует только успешный весь candidate; AI выполняет свою принятую ограниченную policy через ту же границу, без дополнительного развития от planner или render. Внутренние AI-команды не являются новой шкалой времени. После load красный AI paused, запуск только явный; успешный blue-end может запланировать отдельный red-end по прежнему scheduler.

Save/load только encode/decode автономного snapshot: не завершают окно/раунд, не начисляют выпуск/науку/добычу, не возвращают fuel/HP/ammo и не вызывают resolver. Не читают latest-map-слот вместо карты сохранения. Отмена/IO failure сохраняет прежнюю партию; иная версия отвергается без миграций/fallback.

## 6. Сгенерированная карта и среда

Браузерный вход Н05: общий generator → строгий checker → обязательная запись карты → создание Conquest. Ошибка не запускает fixed fallback. [Контракт генератора](GALAXY_GENERATOR.md) остаётся текущим.

`session.galaxy.map` — неизменный канонический **начальный** snapshot генератора (schema/rules 1/1). `session.galaxy.systems` — текущие ownership/exploredBy; маска видимости выводится из текущих колоний, присутствия и scanner. Pipeline получает definition/adjacency через карту конкретной партии, без глобальной current map. Начальный snapshot нельзя переписать захватом или будущим терраформированием.

Действующие встречи обходят системы именно этой карты; галактические координаты не передаются тактическому resolver. [galaxyCampaign.test.ts](../tests/galaxyCampaign.test.ts) содержит оплаченные маршруты обеих сторон к двум гарантированным стартовым целям, автономный round-trip и следующий ход, добычу/сканер и независимость боя от координат.

Н10 вводит отдельно текущую runtime-среду, Н11 меняет её. После их принятия экономический расчёт/добыча текущей транзакции читают среду S0, следующий прогноз — новую среду C; обновление среды не меняет начальный map или военные цели до Н18. Требуемые новые fields/producers/consumers вводятся в соответствующих этапах, не здесь.

## 7. Действующее / новое / не входит

| Область | Действующее | Новый согласованный контракт | Не входит в Н01 |
| --- | --- | --- | --- |
| Время | Две стороны, parity turn; fixed-step 0,05 с | Различать окно/own-turn/раунд/такт/кадр; round без повторного развития | Новый scheduler или ручной пошаговый бой |
| Развитие | Доход/мягкое содержание/FIFO/+1 research/mining | S0/D один раз; рост/очки/проекты без пересчёта | Формулы, цены, caps и fields населения/очков |
| Эффекты | Unlock/range нынешнего дерева, автономные design | Экономика со следующего own-end; бой по закреплённому design | Новые effects handlers, refit или смена дерева/save |
| Потери/захват | Добыча до боя, исходное содержание, очередь без refund | Сохранить этот порядок, явно применить к новым механикам | Награды/передача очередей/новые условия победы |
| Границы | Итоговая валидация; Conquest `ok/message`, без economy receipt | Новый API позже даёт code/message и фактическую квитанцию | Переписывание действующего executor/UI/codec |
| Карта | Generated initial snapshot и runtime ownership/knowledge | Отдельная runtime-среда в Н10, не мутация map | Длины линий/metric travel/P>2 |
| Проверки | Существующие regression suites | Матрица ниже для будущих поставок | Запуск будущего Н03-runner или выдача документа за runtime-приёмку |

## 8. Ручная приёмочная матрица и план регрессий

Числа будущих points ниже — **независимые иллюстрации**, не баланс; эти сценарии расписаны вручную, не исполнялись как новые тесты.

| Сценарий | Oracle / критерий |
| --- | --- |
| Два своих конца и один чужой | Blue окна 1/3, red окно 2: blue получает D дважды, red один раз. При нынешней одной неизменной колонии без ships blue 100/50 → 110/55 → без изменения на red-end → 120/60; research progress +2 при достаточно длинной активной технологии |
| 0/1/несколько боёв | При одинаковом S0 колониальный D начисляется один раз для любого количества встреч. Потери/владение могут изменить следующий прогноз, не число начислений текущего |
| Технологический порог | Иллюстрация: S0 science=10 points/own-turn, progress=20/30, исходный credits-выпуск=100; D даёт +10 → 30 и +100. Открывается +20% credits: текущий выпуск остаётся 100, следующий forecast=120; нет второго +10 science или автоматического следующего открытия |
| Рост/изменение среды | Исходные работники/среда дают D; рост и завершение проекта не меняют D/добычу текущего окна. Следующий own forecast читает новых работников/среду |
| Прибытие добытчика и гибель | Собственный ship прибывает в barren в F, получает один yield в G, погибает в H: один платёж содержания и один yield; ship/operations удалены, minerals не забираются назад |
| Захват колонии | Red-end при исходной red-колонии даёт доход только red; затем sole blue armed presence захватывает её без второго дохода blue. На blue-end с исходной red-колонией дохода этой колонии нет ни red, ни blue; следующий blue-end включает её |
| Завершённая/старая очередь при захвате | FIFO мог завершить head в D, но I удаляет его вместе со старой очередью без refund/deploy; global counter сохраняется. Не начислять очки новому владельцу |
| Поздний отказ | Вторая встреча требует battle ID сверх MAX_TURN либо последняя итоговая проверка отклоняет C: казны, прогресс, arrivals, потери первой встречи, владение, turn/ID полностью равны S0; без frames/receipt частичного успеха |
| Exact/+1 | Точный cap допускается, +1 отклоняет весь end. Валовой overflow до содержания не спасается списанием; при MAX_TURN нет начислений/arrival. Номер отчёта равен завершённому окну |
| Timeout/нет колоний | Timeout сохраняет обе стороны/потери без захвата; нет колоний → research paused, ships разрешены, upkeep сохраняется; не выдавать автоматическую победу |
| Полный раунд | Blue-end → red-end: один round tick, каждый D один раз. Отказ red-end → нет round tick; успешный повтор с актуальным input → один tick. Completed посреди раунда не создаёт фиктивного развития |
| Save/load и replay | Полный snapshot после load равен сохранённому, fuel/HP/ammo/progress/turn не изменены, AI не scheduled. Следующий законный end равен непрерывной ветви. Pause/replay/speed не меняют snapshot |
| Карта партии и приватность | Повторить маршрут/добычу/встречу на сгенерированных картах разных seed, обе стороны; initial map неизменен, ownership меняется. Own прогноз не содержит enemy treasury/design/research |
