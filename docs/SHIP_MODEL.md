# Модель космического корабля

## Описание

Ниже описана **legacy-модель ShipComponents**, оставшаяся у createCustomShip и в адаптере, не новый проект из верфи. Все демонстрационные пресеты, включая добытчик, и боевые фабрики уже проектные; актуальные правила v2, служебные слоты, трюмы и испытания описаны в [SHIP_DESIGN](SHIP_DESIGN.md). DesignedShip не наследует Ship/CombatShip; общие операции движения/энергии/груза находятся в ShipRuntime, тактика подключается независимо. Legacy CombatShip остаётся instanceof Ship, конструктор старого Ship и его mutable-компоненты сохранены. Партии обеих моделей хранятся в ShipState; cargo возвращает копию с weight, getCargo — с mass. usedSpace/currentWeight вычисляются из партий/оборудования. Старые эффекты MINING/REPAIR/SCANNER/CARGO_EXPANSION в этом API не исполняются; пассивное расширение объёма реализовано только у канонического cargoExpansion. Единицы и границы численных операций теперь общие: см. [правила](SHIP_DESIGN.md#единицы-и-правила).

Модель космического корабля состоит из трех основных компонентов:

### 1. Источник энергии (Power Source)

Отвечает за запас энергии корабля. Влияет на:

- **Тактическая автономность** — запас ограничивает непрерывную оценку движения только при расходе выше генерации; это не стратегическая дальность
- **Стоимость** - более мощные источники стоят дороже
- **Выработка энергии** - скорость восстановления энергии

Типы источников энергии:

- Солнечные панели (1000 кредитов, 100 энергии)
- Ядерный реактор (5000 кредитов, 500 энергии)
- Термоядерный реактор (15000 кредитов, 1500 энергии)

### 2. Двигатель (Engine)

Определяет скорость и маневренность корабля. Влияет на:

- **Скорость полета** - чем мощнее двигатель, тем быстрее летает корабль
- **Тяга** - влияет на скорость с учетом веса корабля
- **Потребление энергии** - более мощные двигатели потребляют больше энергии
- **Стоимость** - более мощные двигатели стоят дороже

Типы двигателей:

- Химический (800 кредитов, скорость 100)
- Ионный (3000 кредитов, скорость 200)
- Плазменный (10000 кредитов, скорость 400)

### 3. Грузовой отсек (Cargo Hold)

Используется для перевозки грузов и установки оборудования. Влияет на:

- **Грузоподъемность** - максимальный вес груза
- **Вместимость** - объем грузового пространства
- **Слоты для оборудования** - количество устанавливаемого оборудования
- **Стоимость** - большие отсеки стоят дороже

Типы грузовых отсеков:

- Базовый (500 кредитов, 100 м³, 50 т)
- Укрепленный (2000 кредитов, 250 м³, 150 т)
- Продвинутый (8000 кредитов, 500 м³, 300 т)
- Тяжёлый (12000 кредитов, 750 м³, 450 т) — для полной комплектации дредноута

Это параметры legacy-модели. Исторический боевой крейсер S1 использовал продвинутый отсек, дредноут — тяжёлый; такие комплекты остались только в тестовой фикстуре. Производственная CombatShipFactory теперь создаёт канонические проекты без этой грузовой модели; см. [фабричные проекты](SHIP_DESIGN.md#фабричные-боевые-проекты).

## Оборудование

Корабли могут быть оснащены различным оборудованием:

- **WEAPON** - Боевое вооружение
- **SHIELD** - Энергетические щиты
- **SCANNER** - Сканеры для обнаружения
- **MINING** - Добывающее оборудование
- **REPAIR** - Ремонтные модули
- **CARGO_EXPANSION** - Расширение грузового отсека

Каждое оборудование:

- Занимает определенное количество слотов
- Имеет вес и стоимость
- Может быть улучшено (уровни Mk1, Mk2, Mk3)

## Использование

Старая сборка явно вынесена в [LegacyShipFactory](../src/legacy/LegacyShipFactory.ts) и [LegacyShipComponentFactory](../src/legacy/LegacyShipComponentFactory.ts). Старые ShipFactory.createCustomShip и импорт entities/ShipComponentFactory работают как deprecated-совместимость. Они сохраняют прежние числа, не превращают старый корабль в проект и не создают новый формат сохранений. Для новой модели используйте ShipFactory.createFromDesign; battle-фабрика отдельно требует боевую готовность.

Входы фабрик проверяются: известные enum-селекторы; имя 1..80 символов, не полностью пробельное (допустимые пробелы сохраняются); уровень — положительное безопасное целое, по умолчанию 1. Уровни выше Mk3 не обрезаются, legacy-проценты остаются прежними. Установка произвольного IEquipment после создания остаётся старым mutable API, не полным каноническим валидатором.

### Создание корабля с помощью фабрики

```typescript
import { ShipFactory } from './entities/ShipFactory';
import { LegacyShipFactory } from './legacy/LegacyShipFactory';
import { PowerSourceType, EngineType, CargoType } from './entities/interfaces/ShipComponents';

// Создать разведчик
const scout = ShipFactory.createScout();

// Создать грузовоз
const freighter = ShipFactory.createFreighter();

// Создать боевой корабль
const warship = ShipFactory.createWarship();

// Создать добывающий корабль
const miner = ShipFactory.createMiner();

// Создать именно legacy-корабль, не проект верфи
const customShip = LegacyShipFactory.createCustomShip(
  'Мой корабль',
  PowerSourceType.FUSION,
  EngineType.PLASMA,
  CargoType.ADVANCED
);
```

### Управление кораблем

```typescript
import { LegacyShipComponentFactory } from './legacy/LegacyShipComponentFactory';
import { EquipmentType } from './entities/interfaces/ShipComponents';

// Установить оборудование
const weapon = LegacyShipComponentFactory.createEquipment(EquipmentType.WEAPON, 2);
if (!ship.installEquipment(weapon)) throw new Error('Оборудование не установлено');

// Загрузить груз
const cargo = {
  resourceType: 'iron',
  amount: 100,
  weight: 50,
  volume: 25
};
if (!ship.loadCargo(cargo)) throw new Error(ship.getCargoMessage());

// Начать движение
ship.startMoving(targetX, targetY);

// Обновить состояние корабля
ship.update(deltaTime);

// Получить информацию
console.log(ship.getInfo());
```

## Характеристики корабля

CombatShip пересчитывает оружие и щиты после успешной установки/снятия оборудования, сохраняя текущую перезарядку и не восстанавливая повреждения. Только новый фабричный корабль получает полностью заряженный щит. Эффекты ремонта, добычи, сканирования и расширения грузового отсека пока не исполняются как отдельные системы.

Корабль имеет следующие расчетные характеристики:

- **Общая стоимость** - сумма стоимостей всех компонентов и оборудования
- **Общий вес** - сумма весов компонентов, оборудования и груза
- **Оценка полёта getFlightEstimate** — учитывает текущую батарею, генерацию, мощность движения и скорость с грузом; при генерации не ниже расхода сообщает, что движение обеспечено. Это непрерывная оценка без боевых расходов/дискретных шагов. getMaxRange сохранён deprecated с прежними числами, в UI не используется
- **Текущая максимальная скорость** - зависит от мощности двигателя и общего веса

Единицы: батарея/выстрел — ЭЕ, генерация/движение — ЭЕ/с, скорость — такт. ед/с, расстояние — такт. ед., update — секунды симуляции. Неверные расход/время/координаты/урон отклоняются без соответствующей операции. Запись текущей энергии вне 0..capacity вызывает RangeError до записи; текущие HP/щит/cooldown требуют конечных неотрицательных значений. Полная валидация произвольной legacy-конфигурации и прямых вложенных координат не реализована.

## Примеры предустановленных кораблей

Ниже исторические комплектации до канонической миграции, не текущие результаты ShipFactory. Актуальные проекты описаны в [SHIP_DESIGN](SHIP_DESIGN.md#гражданские-проекты); точные legacy-числа закреплены в [регрессиях](../tests/legacyBoundary.test.ts).

### Разведчик

- Солнечные панели
- Ионный двигатель
- Базовый грузовой отсек
- **Стоимость:** ~4300 кредитов
- **Особенность:** Быстрый и экономичный

### Грузовоз

- Ядерный реактор
- Химический двигатель
- Продвинутый грузовой отсек
- **Стоимость:** ~13800 кредитов
- **Особенность:** Большая грузоподъемность

### Крейсер

- Термоядерный реактор
- Плазменный двигатель
- Укрепленный грузовой отсек
- **Стоимость:** ~27000 кредитов
- **Особенность:** Высокая скорость и мощность

### Добытчик

- Ядерный реактор
- Ионный двигатель
- Укрепленный грузовой отсек
- Добывающий модуль
- **Стоимость:** ~14000 кредитов
- **Особенность:** Оборудован для добычи ресурсов
