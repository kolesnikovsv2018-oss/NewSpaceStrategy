# Н17 — несколько участников: комплект подзаданий

**Этап:** Н17 (подэтапы Н17.1–Н17.8). **Предпосылки этапа:** Н05, Н16 — приняты.  
**Родительское задание:** [n17-multiple-factions.md](../n17-multiple-factions.md).  
Каждое подзадание выполняется с обязательным [общим контрактом](../00-execution-contract.md)
и [основным планом](../../plan-2026-10-09.md). Комплект дробит этап по правилу указателя
заданий: вертикальные подзадачи, каждая со своими схемами/командами/UI/AI/save и проверками
либо честно самостоятельным контрактным результатом.

## Правила выполнения комплекта

- До кода должен быть утверждён результат Н17.1; спорные решения не подменяются defaults
  ([контракт §1.5](../00-execution-contract.md)).
- Н17.2 сохраняет опубликованную игровую границу P=2; диапазон расширяет только Н17.6
  после готовности встреч, дипломатии и контроллеров — промежуточные состояния не публикуют
  «половину схемы с неработающими встречами».
- Каждое подзадание публикуемо само по себе: после него партия P=2 играется, save/load
  работают, `yarn test`/`typecheck`/`build` проходят.
- Журнал ведёт исполнитель вручную: при старте Н17.1 поставить строку [Н17](../task-status.md)
  в «В процессе» с пометкой о разбивке Н17.1–Н17.8; «Выполнено» — только после приёмки Н17.8.
  Подэтапы отдельными строками не открывать.
- Н-граф не меняется: Н18 по-прежнему требует Н17 целиком. Мирная песочница (campaignMatch,
  joint-survey) и её формат не мигрируют.
- Отчёты подэтапов — в `reports/<фактическая дата>/` по навыку orion-task-report;
  план комплекта `plan-n17.md` создаёт Н17.1.
- Коммит/push — только по прямому запросу.
