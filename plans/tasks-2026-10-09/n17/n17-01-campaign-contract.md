# Н17.1 — игровой контракт многосторонней кампании

**Этап:** Н17.1 (подэтап [Н17](../n17-multiple-factions.md)). **Предпосылки:** Н05, Н16. **Статус:** задание, не реализация.  
Выполняй с [общим контрактом](../00-execution-contract.md) и [основным планом](../../plan-2026-10-09.md).

## Промпт и завершённый результат

До кода зафиксируй продуктовые решения Н17: диапазон участников, политику разрешения встреч,
семантику расписания, elimination, формат контроллеров, метаданные участников и версии
форматов. Это документационный/контрактный этап: runtime не меняется, игровых механик
не добавляет. Результат — утверждённый пользователем контракт, на который опираются
Н17.2–Н17.8.

Опоры: [родительское задание](../n17-multiple-factions.md),
[CAMPAIGN_CONQUEST](../../../docs/CAMPAIGN_CONQUEST.md),
[CAMPAIGN_DIPLOMACY](../../../docs/CAMPAIGN_DIPLOMACY.md),
[GALAXY_GENERATOR](../../../docs/GALAXY_GENERATOR.md), стартовые версии
[ConquestSaveManager](../../../src/utils/ConquestSaveManager.ts) (save 18 / rules 15)
и [rulesSnapshot](../../../src/domain/campaignRules.ts) (13).

## Работы

1. При старте отметь строку [Н17](../task-status.md) «В процессе» с пометкой о разбивке
   на Н17.1–Н17.8; прочитай результаты Н05/Н16 и комментарии; проверь git status.
2. Проверь предпосылки по фактическому коду, тестам и отчётам, не по существованию Markdown:
   [Н05](../n05-galaxy-data.md), [Н16](../n16-diplomacy.md),
   [отчёт Н16](../../../reports/2026-11-06/02-n16-diplomacy.md).
3. Перечисли нерешённые решения и предложи конкретный вариант по каждому, запросив
   подтверждение пользователя; не подменяй отсутствие решения default:
   - диапазон P: в пределах поддержанного генератором 2–8 при действующем минимуме миров
     ≥ 3×P; нижний предел миров в UI = max(6, 3×P); более широкий диапазон — отдельное
     изменение профиля;
   - encounter policy: deterministic pairwise последовательность двухсторонних боёв реальным
     BattleManager с versioned маркером (например `conquest-encounters-v2`) либо
     multi-faction hostile selection внутри одного боя; зафиксируй выбор и границу честности
     «не объявлять одновременный бой, если результат последовательный»;
   - расписание: ordered participants `player-01..player-0P` из snapshot; активная
     позиция/фаза; монотонные turn/revision; round = полный круг; turn растёт на каждый
     выполненный или пропущенный ход;
   - elimination: сторона выбывает только без колоний и без кораблей; пропуски не застревают
     в раунде и сроках договоров; победа остаётся all-planets-v1 без новых условий;
   - контроллеры: один актуальный формат `local` либо человек + несколько AI (например
     `{ mode: 'campaign', human: 'player-NN', aiPolicy: 'conquest-v1' }`); прежние сохранения
     после bump отклоняются явно, без миграций;
   - metadata участников: имя из карты, фиксированная палитра цветов по позиции, хранение
     в save-блоке participants; запрет вывода цветов/имён из enum;
   - мирная песочница joint-survey: не мигрирует, сохраняет принятый формат;
   - версии: save 19 / rules 16 как цель этапа (уточнить по факту изменений Н17.2–Н17.5);
   - горизонты диагностики P=3/max согласуются отдельно и не переписывают двухсторонний
     cutoff 200.
4. Оформи принятые решения в новом документе
   [docs/CAMPAIGN_MULTI_FACTION.md](../../../docs/CAMPAIGN_MULTI_FACTION.md) со ссылками
   на родителя и затронутые документы; обнови оглавление docs при необходимости.
5. Создай план этапа `reports/<фактическая дата>/plan-n17.md` по образцу plan-n16:
   границы подэтапов, версии, матрица приёмки родителя с распределением по Н17.2–Н17.8.
6. Проверь согласованность: ни один пункт не противоречит родительскому заданию и принятому
   Н16; Н-граф не меняется.

## Приёмка и проверки

- Каждое решение подтверждено пользователем явно; спорные варианты не приняты молча.
- Документ фиксирует стартовые (save 18 / rules 15 / rules snapshot 13) и целевые версии;
  расхождение с фактом кода исключено.
- `git diff` не содержит изменений src/tests (только docs/plans/reports); тесты не требуются,
  runtime не менялся.
- Ссылки документа проверены; матрица приёмки покрывает все пункты родителя без добавления
  новых обещаний.

## Не входит и независимая поставка

Без реализации схем/команд/UI/AI, без изменения форматов и версий. Н17.2 начинается только
после утверждения этого результата.
