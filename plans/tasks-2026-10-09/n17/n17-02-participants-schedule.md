# Н17.2 — платформа состояния: участники `player-NN` и расписание ходов

**Этап:** Н17.2 (подэтап [Н17](../n17-multiple-factions.md)). **Предпосылки:** Н17.1 (утверждённый контракт), Н05, Н16. **Статус:** задание, не реализация.  
Выполняй с [общим контрактом](../00-execution-contract.md) и [основным планом](../../plan-2026-10-09.md).

## Промпт и завершённый результат

Переведи состояние единой военной кампании на стабильные идентификаторы участников
`player-NN` из snapshot карты и введи расписание ходов: активная сторона определяется
расписанием, не чётностью. Обобщи per-faction контейнеры, введи утверждённый формат
контроллеров, подними версию сохранения. Опубликованная игровая граница остаётся P=2:
браузер создаёт и загружает двухсторонние партии через новый конвейер; расширение
диапазона — только Н17.6.

## Работы

1. Проверь результат Н17.1 по коду/отчёту и git status; подтверди статус [Н17](../task-status.md)
   «В процессе».
2. `participantIdSchema` (`player-NN`) — канонический тип участника военной кампании;
   `getGalaxyDefinition(map)` возвращает участников 1:1 без маппинга «первый blue,
   остальные red»; фиксированный мирный сценарий сохраняет blue/red.
3. Records по участникам вместо жёстких `{blue, red}`: казны сессии, `surveys`, `research`,
   `researchJournal`, каталоги проектов Н05а — zod-records с инвариантами «ровно участники
   кампании, никаких чужих/недостающих ключей»; циклы по `factionIdSchema.options`
   в валидаторах и `reveal` заменены списком участников.
4. Новый модуль расписания: ordered participants, active index/phase, монотонные
   turn/revision, round = полный круг; skip исключённых; active в сессии/конквесте берётся
   из расписания (вместо `turn % 2 ? 'blue' : 'red'`); устрани двойственность `activeFaction`.
5. Контроллеры по Н17.1: `local` либо человек + несколько AI; `getControllerKind` без
   жёсткого red; авторизация команд по расписанию и контролю до действий; P=2 поведение
   сохранено. Схема сессии параметризуется списком сторон: мирная ветка сохраняет принятый
   формат, военная использует participant IDs; второй актуальный формат мирных сохранений
   не появляется.
6. Победа all-planets-v1 обобщена на список участников; `createConquest` создаёт казны,
   знания, исследования, каталоги и стартовые корабли для всех участников карты.
7. Caps: корабли/группы/проекты per faction с глобальными пределами массивов без множителя
   «×2» (правило из Н17.1).
8. Save: bump версий из Н17.1; полный снимок с participants/schedule/controls; прежние
   версии получают явный отказ; статические фикстуры заменены новыми оплаченными сценариями
   актуальной версии (прецедент `upgrade-n15-fixtures.mjs`); save round-trip.
9. UI-минимум: браузерный диалог и сцена работают через participant IDs для P=2; цвета/имена
   из metadata участников (палитра Н17.1); выбор P остаётся заблокированным на 2 до Н17.6;
   мирная песочница не мигрирует.
10. Регрессии: схемы/инварианты/round/turn, заморозка входа, detached output, отсутствие
    автозапуска scheduler/AI при load.

## Приёмка и проверки

- P=2 механически идентична принятой: правила, команды, коды ошибок, результаты; меняется
  только идентичность и расписание.
- Ровно одно развитие на собственный endTurn; round инкрементируется после последнего
  в круге; skip не ломает полный круг.
- Человек не командует AI-стороной; контроллер enforced до действий; observers не меняют
  active/control.
- Save/load oracle на P=2; сохранения прежней версии получают явный отказ без изменения
  состояния или файлов.
- Лишний/недостающий ключ участника в любом record отклоняется; инварианты покрыты
  регрессиями.
- Полный `yarn test` (общая схема/кодек), `typecheck`, `build`; настоящий браузер
  1280×720 и 390×844: новая кампания P=2, ход, save/reload/load, cancel.
