**Дата:** 2026-10-09. **Статус:** Г01–Г03 и браузерная интеграция Г04/Н05 для двух участников реализованы; [отчёт интеграции](../reports/2026-10-09/05-browser-galaxy-integration.md).
**Обязательная часть промпта:** [контракт исполнения](tasks-2026-10-09/00-execution-contract.md).  
**Связь:** [основной план](plan-2026-10-09.md), Н05/Н14/Н17 и [указатель заданий](tasks-2026-10-09/README.md).
**Отчёт о подготовке:** [02 — Генератор и этапные промпты](../reports/2026-10-09/02-generator-and-stage-prompts.md).
**Реализация и проверки:** [04 — генератор галактики Г01–Г03](../reports/2026-10-09/04-galaxy-generator.md); [контракт формата и CLI](../docs/GALAXY_GENERATOR.md).

**Данные:** генерация, кодирование, чтение и импорт используют только актуальную новую версию карты/профиля/правил. При смене версии обновляются все потребители и fixtures; иной формат получает явный отказ без преобразования или fallback.

## 1. Задача для исполнителя

Разработай детерминированный генератор карты Orion. На вход обязательно передаётся количество миров. Готовая карта содержит ровно это число миров **включая стартовые**, имеет связную топологию и честные стартовые условия. Результат каждого успешного вызова пользовательского CLI обязательно записывается в отдельный JSON-файл.

Пользователь подтвердил:

- У каждого участника, включая оппонентов, ближайшие миры достижимы **из его собственного стартового мира** с начальными возможностями его колонизационных кораблей.
- Основное сохранение — **JSON-файл на диске через CLI**. Браузерная библиотека, export/download и localStorage не заменяют это требование.

Генератор не обязан сразу вводить население, научную экономику или многосторонний бой. Г01–Г03 — самостоятельный инструмент; Г04 подключает уже проверенную карту к действующим границам нового режима.

## 2. Подтверждённые факты и решения перед кодом

Текущая [campaign.ts](../src/domain/campaign.ts) сохраняет фиксированные шесть систем для мирной демонстрации, но Conquest уже принимает проверенный сгенерированный snapshot с `world-NNN` ID; игровые стороны пока blue/red. Текущие [campaignShips.ts](../src/domain/campaignShips.ts) и Conquest используют соседние линии, fuel 3, расход 1, прибытие за свой ход; длины линий в формате пока нет. Отдельной утверждённой модели «колонизационного двигателя» пока нет. [getFlightEstimate](../src/domain/flightEstimate.ts) оценивает тактическую энергию и не годится для стратегической достижимости.

Принятые решения:

1. Один мир соответствует одной системе с одной планетой; worldCount считает эти записи. Несколько планет в системе остаются будущей версией.
2. Число участников задаётся при генерации/старте; первая реализация поддерживает 2–8. Импорт карт с числом участников более двух в кампанию требует Н17.
3. Профиль `balanced-start-v1` гарантирует два ближайших нейтральных пригодных мира на участника. При P участниках требуется `worldCount >= P × 3`; недостаточное значение явно отклоняется.
4. Каждый участник получает один собственный домашний мир; все дома и гарантированные цели имеют равные начальные характеристики.
5. Верхняя граница — 256 миров; квадрат координат `[0,1000] × [0,1000]`, минимальное разделение центров — 10. Типы в первой версии: `habitable`/`barren`; среди дополнительных незарезервированных миров ровно 70% пригодны (округление вниз), дома и гарантированные цели всегда пригодны.
6. JSON записывается в UTF-8 с Unicode-названиями на русском и английском. Искусственный byte cap не устанавливается.
7. Размещение проверяет фиксированную решётку 33×33; каждый кандидат рассматривается не более одного раза. Профиль ограничивает степень топологии четырьмя.

Н05 уже выполнен: дальнейшие этапы расширяют этот общий формат/профиль, а не создают несовместимый формат или второй генератор. Н10 обновляет каталог сред, Н14 вводит доменную длину и метрическую достижимость, Н17 включает P>2 в существующих браузерных настройках. Каждый из этих этапов обновляет checker/CLI/browser/fixtures в собственной поставке; исходная карта не меняется при runtime терраформировании.

## 3. Вход, результат и ошибки

Чистая граница `generateGalaxy(unknown)`:

```text
request = {
  worldCount, participantCount, seed, generatorVersion, profileId
}
result = {ok:true, map}
      | {ok:false, code, message}
```

Реализован strict request `{worldCount, participantCount, seed, generatorVersion, profileId}` без лишних полей. worldCount — конечный safe integer; seed — целый 1..0xffffffff. Профиль содержит число участников, гарантированное k=2 и ограничения топологии/среды. CLI по умолчанию принимает 2 участника; seed создаётся **один раз на IO-границе** и записывается в JSON. Чистый домен всегда получает явный seed.

Отдельная граница `generateAndSave`/CLI отвечает за кодирование и запись. Чистая генерация для тестов не выполняет IO; пользовательский успех выдаётся только после успешной записи файла.

Предусмотрены ошибки: неверный запрос, невозможные стартовые ограничения, неизвестный профиль/версия, недопустимая карта, отказ записи, существующий выходной файл. Раскладка рассматривает фиксированную сетку максимум из 1089 точек без повторных попыток. Ошибка не возвращает fallback-карту и не объявляет сохранение успешным.

## 4. Точный критерий достижимости

Для каждого home участника a:

- Найди k ближайших **нейтральных** миров по физическим координатам карты; ties — стабильный ASCII ID. Экранные координаты/масштаб canvas не участвуют. Стартовые миры исключаются из списка кандидатов, но не из worldCount.
- Каждый такой мир имеет разрешённую начальной технологией среду, свободен и связан с home прямой разрешённой линией.
- Вызови общую чистую функцию доступности маршрута с **реальным начальным стратегическим профилем** этого участника. Она учитывает правила перехода, запас топлива, начальные открытия, а в метрической версии — длину перехода и расход.
- Резервируемые стартовые миры разных участников не пересекаются. Достижение не требует исследования, заправки в несуществующей колонии, пересечения вражеского дома или захвата.
- Достижимость означает прибытие и возможность последующей законной колонизации, а не бесплатную разведку из debug-состояния. Мир может сначала требовать разведки; начальная разведка/сканирование не должны делать маршрут недоступным навсегда.

**До Н14:** поддержать явно названную `initial-lanes-v1`: одна прямая линия, начальный бак/расход текущего стратегического правила, допустимая среда. Не выводить метры или скорость из тактического двигателя. Физическая близость задаёт порядок соседей, но не стоимость полёта в этой версии.

**После Н14:** заменить актуальную политику на `initial-distance-v1` с общим runtime-калькулятором пути, начальным snapshot двигателя/бака и distances. Обновить формат, генератор, checker, импорт и fixtures согласованно; новые карты проверять тем же predicate, который реально разрешает отправку в кампании. Для игры по обновлённым правилам генерировать JSON заново.

Не писать отдельную более мягкую проверку только для генератора. Отдельные unit oracle проверяют арифметику доступности, интеграционные тесты — настоящие команды отправки/прибытия/колонизации.

## 5. Построение карты

1. Проверить возможность всех ограничений до RNG/IO.
2. Использовать [seededRandom](../src/domain/seededRandom.ts) с отдельными потоками placement/topology/world-types; никакого Date.now/Math.random в генераторе. ID — стабильные `world-...`, не UUID по времени.
3. Разместить стартовые области с заранее зарезервированными k мирами. Сначала конструктивно обеспечить гарантии старта, затем добавлять оставшиеся миры.
4. Разместить дома достаточно раздельно; не допустить, чтобы случайный мир оказался ближе зарезервированных, но был непригоден/недостижим. Финальный nearest-k считается заново по всем нейтральным мирам.
5. Стартовые пакеты сделать равными по числу достижимых пригодных миров и начальной вместимости/ресурсам согласно профилю. Геометрическое разнообразие не объявлять доказанным балансом.
6. Создать обязательные линии к ближайшим мирам и связующий остов всей карты, затем дополнительные линии с ограничением степени. Нет петель, дубликатов обратных линий и ссылок на отсутствующие ID.
7. Глобальная связность не означает, что весь космос доступен начальному флоту: дальние области могут требовать новых технологий, но старт не блокируется.
8. Применить типы/характеристики миров по сохранённой таблице профиля, не подменяя гарантированные стартовые цели непригодными.
9. Провести полную независимую валидацию, включая exact count, nearest-k, достижимость, связность и стартовую симметрию возможностей.
10. Ограничить попытки и число операций. Исчерпание возвращает ошибку, не бесконечный retry и не подмену seed.

Порядок обхода, округление физической дистанции, равные расстояния и порядок массивов должны быть каноничны. Один input/seed/версия дают одинаковые JSON bytes; не включать в канонический файл дату создания или случайное имя пути.

## 6. JSON и файловый адаптер

Предлагаемый envelope:

```text
{
  format: "orion-galaxy-map",
  schemaVersion,
  generator: {version, seed, worldCount, profileSnapshot},
  map: {
    worldTypes,
    worlds: [{id, name, physicalPosition, worldTypeId, ...}],
    lanes: [{fromId, toId, distance}],
    starts: [{factionId, homeWorldId, initialCapabilities}],
    initialTravelPolicy
  }
}
```

Фактический формат реализован в [GALAXY_GENERATOR.md](../docs/GALAXY_GENERATOR.md). В JSON хранится **полная карта**, а не только seed, ссылка на каталог или state партии. Владение после начала игры, исследования, UI-флаги и receipt сюда не входят.

Кодек: UTF-8 JSON без искусственного byte cap, strict version/shape, уникальные ID, известные ссылки/типы, конечные координаты, один дом на участника, отсутствие повторных линий, полный генерационный инвариант. Имена могут содержать Unicode, включая русский и английский. Не доверять заверению `validated:true` внутри файла. Encode тоже проверяет всю карту.

CLI-интерфейс для реализации:

```text
yarn generate:galaxy --world-count 40 --participants 4 --seed 12345 --output maps/galaxy-40-12345.json
yarn generate:galaxy --world-count 40 --output maps/galaxy-40.json
```

Команда добавлена в package.json. `--world-count`/`--output` обязательны, `--participants` default=2, без `--seed` CLI один раз создаёт seed на IO-границе. Не перезаписывай существующий файл: возвращай конфликт. Каталог назначения должен существовать; произвольный shell-code не строится.

Используй поддерживаемый существующим toolchain способ запуска TS-инструмента без второго lockfile. Node native TypeScript не гарантирует поддержку текущих extensionless imports — проверь выбранный runner/сборку реально. Новые зависимости вводи только при доказанной необходимости.

Запись полного файла: безопасный временный файл в каталоге назначения → атомарная публикация hard link без перезаписи чужого файла → успех. Конкурентное создание destination получает ошибку. Временные файлы очищаются точечно. Файловая система должна поддерживать hard links; устойчивость к отключению питания не обещается.

JSON round-trip сохраняет всю карту; CLI печатает seed/версию/число миров и фактический путь только после завершения IO. При запрете записи — stderr и ненулевой exit, нет успешной «сгенерированной и сохранённой» карты.

## 7. Самостоятельные этапы разработки

### Г01 — карта, профиль и проверка достижимости — выполнено

**Предпосылки:** нет.
Реализованы общий чистый format/schema/codec, профиль переменного количества участников и `initial-lanes-v1`, checker nearest-k/стартовых возможностей. Добавлены генерационные fixture-основы и повреждённые cases. Это документированный проверяемый API, не новый игровой режим; метрические характеристики не подключены.

**Приёмка:** выполнена. Отклоняются неверные ID/ссылки/count/версии; проверены минимумы и пределы, detached round-trip, Unicode names, ближайший непригодный и недостижимый мир. Ограничение размера сериализованного файла не применяется.

### Г02 — детерминированный генератор — выполнено

**Предпосылки:** Г01.  
Реализован чистый детерминированный генератор с конструктивными стартовыми пакетами, связностью, заданным worldCount и конечным бюджетом. Нет IO и изменений действующей кампании.

**Приёмка:** минимум допустимого N (6/2), N+1 и максимум (256/8) покрыты; 100 фиксированных seed для малого (6/2), среднего (64/4) и максимального (256/8) профиля. Все результаты проходят checker. Дополнительно 20 seed для каждого P=2…8 проходят с перестановкой всех массивов карты. Одинаковые seed дают одинаковую карту; смена геометрического слота участника не ломает гарантии nearest-k.

### Г03 — CLI и обязательное сохранение — выполнено

**Предпосылки:** Г02.  
Добавлены yarn-команда, строгие arguments, файловый адаптер и документация. Успех — только валидный реальный JSON-файл, открываемый кодеком; browser-зависимостей нет.

**Приёмка:** реальные subprocess-прогоны с world-count/participants/seed/output и профилем по умолчанию; файл читается кодеком. Повторный вывод в существующий путь не портит его; write failure/collision/invalid input дают ненулевой exit без публикации неполного файла. Тестовые файлы изолированы во временном каталоге.

### Г04 — браузерная карта в кампании — выполнено для двух участников

**Предпосылки:** Г01–Г03 и реализованные S3/S4. Г04 и Н05 — одна интеграционная поставка, не зависимость друг от друга. Метрическую policy вводит позднее Н14, P>2 в игре — Н17; они не блокируют принятую двухстороннюю интеграцию.
Вместе с уточнённым Н05 запускай тот же генератор непосредственно при старте браузерной кампании: 6–256 миров на выбор, два заблокированных участника. Обязательная запись актуального JSON в единственный слот последней карты предшествует старту; ошибка сохраняет текущую партию и прежние байты. Map repository port предусматривает будущие серверные save/load, но backend не реализуется. Полный snapshot карты принадлежит партии; загрузка прогресса не генерирует её заново. UI не запускает Node filesystem. Файловый import карты не входит в эту поставку.

**Приёмка:** CLI и browser при одинаковых входах сохраняют одинаковый JSON; обе стороны настоящими оплаченными кораблями достигают гарантированных целей; save/reload/load даёт тот же следующий результат независимо от latest-map-слота. Настройки, ошибки/отмена/lifecycle, динамические UI/AI/победа проверяются вместе с Н05. Для будущей metric-v1 отдельный тест должен доказать согласованность checker/команды после Н14.

## 8. Не входит и завершение

Не вводить одновременно сетевую игру, БД, редактор карт, бесконечную галактику, сложную физику орбит или новую модель боя. Большие карты не объявлять быстрыми без измерений.

По каждому Г-этапу выполнить общий контракт проверок/закрытия. В отчёте указать подтверждённые диапазоны N, матрицу seed, политику достижимости и реальные проверки файлов отдельно от browser. Публикуемость — отсутствие зависимости от следующих Г-этапов; реальный push только по запросу.
