# Orion — план развития по результатам аудита

- Дата: 2026-09-07.
- Цель: связать создание проекта корабля с воспроизводимым испытанием, затем построить минимальный стратегический цикл в духе Master of Orion.
- Состояние при аудите: набор отдельных прототипов верфи, визуализации и автобоя. Переписывание с нуля и смена движка не требуются.

## Стек и исходные факты

TypeScript strict, Phaser 3, Vite 4, Yarn Classic, browser-only. Установлены Phaser 3.90.0, TypeScript 5.9.3, Vite 4.5.14. UI — Phaser Graphics/Text/Container; localStorage/JSON реализованы как неподключённая заготовка. MainScene — заглушка; экономики/галактики/исследований нет.

Исходная сборка останавливалась на 8 TS6133 в двух панелях. Проверки исполнения подтвердили одинаковые характеристики оружия всех боевых пресетов, два обновления модели за кадр, неверный учёт потерь и отказ установки части оборудования крейсера/дредноута. Производительность в FPS не измерялась.

- [ ] Фиксированный шаг симуляции, внедряемый seeded RNG, повторяемые сценарии и серии боёв.
- [ ] Приоритет целей, дистанция, построения, прикрытие, отступление, пауза/ускорение и объяснимый отчёт.

- [ ] Отделить свободный редактор компонентов разработчика от ограниченных исследованных вариантов кампании.
- [ ] Цвет — фракция, силуэт — корпус, эффекты — тип модуля; не определять роль по имени корабля.
- [ ] Профилировать целевые размеры флотов; обновлять UI по изменению/таймеру, кэшировать статическую графику.
- [ ] Пулы эффектов, пространственный индекс и Worker вводить только при подтверждённой необходимости.
- [ ] После тестового покрытия планово обновить устаревшие инструменты сборки; не смешивать апгрейд стека с исправлением механики.

## Правила выполнения

Зависимости: S0 → S1 → S2 → S3; S4 вводится по мере необходимости после стабилизации. Не расширять текущую задачу до всех будущих этапов. После каждой задачи обновлять профильные навыки и создавать новый отчёт в reports/{дата выполнения}/. Непроведённые проверки и открытый долг указывать явно.
