## Реализация

### Runtime и собственное знание

[worldEnvironment](../../src/domain/worldEnvironment.ts) задаёт каталог
habitable/toxic/barren и строгий query. Conquest хранит отдельную
environment-запись каждого world ID и собственные surveys сторон
с последним observedType. Начальное состояние создаётся из проверенного
canonical snapshot, не из внешнего изменяемого аргумента карты.

Ownership/population/assignments проверяются по текущей среде.
Структурная военная schema не запрещает владение только из-за начального
barren; полная Conquest schema требует допустимую текущую среду и knowledge.
Низкий military-session API явно отвергает старые map-only explore/colonize:
новые проверки нельзя обойти прежней географической командой.

Рост, вместимость, выпуск, добыча и UI/AI читают общий текущий тип.
Runtime не прогоняется через checker долей начальной карты.
Исходные habitable+toxic остаются военными целями независимо от unlock
и будущей runtime-смены. Это проверено отдельной диагностической
barren→habitable записью, включая ownership/K/codec и неизменный знаменатель.
Это проверка инфраструктуры для Н11, не реализованное терраформирование.

Вне обзора сохраняется собственный изученный тип без актуального owner/врагов.
В обзоре ранее изученная среда доступна в актуальном виде; успешная
команда обновляет её snapshot. Неизученный мир не получает бесплатного survey.
Query не мутирует вход.

### Изучение, адаптация и основание

Survey — мгновенная команда10/5 без смены хода: свой стоящий корабль
либо разрешённый scanner в радиусе стратегической дальности стороны,
без вражеского присутствия. Дома изучены с начала.
Повтор ALREADY_SURVEYED не списывает деньги, недостаток одной валюты
и любой отказ атомарны.

Toxic имеет K6000/absolute12000 и обычные базовые рост/выпуск.
Корневой toxic-adaptation3000 разрешает только основание.
Импорт дерева обязан сохранять достижимые адаптацию и дальность.

Общий availability query использует безопасный порядок:
наблюдение→survey→занятость/тип→враги/колонизатор→адаптация→жители/ресурсы.
UI и AI не вычисляют свою альтернативную законность.
Явный colonize расходует выбранный корабль, переносит1000 жителей
и платит20/10. Вооружённое прибытие не основывает нейтральный мир.

Захват уже существующей колонии не требует своей адаптации/колонизатора:
P/остаток сохраняются, управление/рост/выпуск работают,
данные среды передаются владельцу. Unlock других toxic-оснований не выдаётся.

### Н09 и защита скрытой информации

Пять modifiers используют явные уникальные selectors worldTypes
для habitable/toxic. Toxic получает рост2%→2,4%,
biosphere K6000→8000 и три выпуска+20%.
Absolute12000, caps/резервы/точность и completed S0 сохранены.
Открытие biosphere внутри endTurn не применяет новый K к уже рассчитанному росту.

Добыча требует изученный фактический barren.
Без этого условия income/treasury позволяли бы угадать неизвестную среду
ещё до survey. Парные скрытые состояния, включая изменение
ранее изученного типа вне наблюдения, дают одинаковые own-view/AI-планы.

### Генератор, UI, AI, сохранение

Map3/generator-v3/balanced-start-v3 сохраняет прямую метрику Д08 без линий.
Дома/две ближайшие начальные цели habitable.
Для E дополнительных миров C=floor(70E/100),
T=0 при E<2, иначе min(C,max(1,floor(20E/100))):
T toxic,C−T habitable,E−C barren.
Минимальная карта6 не обязана иметь toxic; новый цикл проверен на8.
CLI/browser/checker/codec обновлены вместе.

Обе раскладки показывают «среда не изучена», изученный тип, цену survey
и причины «нужна адаптация/занят/нет колонизатора/ресурсов».
У own toxic показан реальный K, а не прежняя константа10000.
Scanner не заменяет научную адаптацию.

AI проходит законный survey/research/colonize из own-view,
с прежними bounded кандидатами/командами, без скрытых типов и будущих механик.
Историческое знание пригодности теперь идёт из surveys, не из exploredBy.

Единственные актуальные версии: **save12/rules9, snapshot7/rules7,
tree6, campaign-tables-v4, map3, baseline8**.
Environment/surveys сохраняются, derived availability/K/forecast — нет.
Иные версии явно отвергаются без миграций/readers/fallback.
Загрузка не читает latest-map и не повторяет survey/исследование.

## Настоящий браузер

В отдельном профиле обычным диалогом создана local карта8.
Неизвестные дополнительные миры выбирались по публичным ID,
без чтения их типов для решения о survey.

Обычными scene-командами назначены1000 industry/4000 research
и настоящим расходом науки заработаны engineering/support/ordnance/capital,
получена дальность1500. Корабль совершил прямой перелёт;
до survey тип скрыт и colonize disabled.

Кнопкой мыши оплачено изучение: в одном прогоне сначала barren, затем toxic,
в повторном сразу toxic. На обоих viewport видны тип и явная причина
ADAPTATION_REQUIRED. Выполнены actual save/reload/load и полный oracle.

Мышью выбран toxic-adaptation; обычными own-end заработано открытие.
Мир всё ещё toxic/P0. Второй save/reload/next oracle совпал.
Кнопкой colonize основана колония: корабль удалён, P1000/K6000,
среда не изменилась. Desktop/mobile screenshots осмотрены отдельно.

Затем полностью оплачен следующий колонизатор229/19,
назначена1 industry и получен progress1/23.
Третий save/reload/load сохранил частичный FIFO, own knowledge и runtime;
следующий полный результат endTurn равен непрерывной ветке.
Одна canvas, корректный native CSS размер, пороги14/44 и отсутствие
runtime exceptions подтверждены в обоих прогонах.

Не полный mouse-only E2E: массовые назначения/часть исследований/ходы
выполнялись обычными scene-командами, без инъекции state/ресурсов/кораблей.
Это не physical touch, real quota/FPS или новая browser-приёмка боя.
Тестовые ключи удалены только из собственного изолированного профиля.
