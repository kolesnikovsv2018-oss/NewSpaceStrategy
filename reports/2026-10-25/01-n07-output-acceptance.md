## Цель и границы

Продолжить сохранённую реализацию Н07, устранить обнаруженные причины
подвисания проверок и завершить труд/выпуск/FIFO/UI/AI/save в Conquest.
Мирные API/формулы и прежние изменения Н06 сохранены.
Н08, здания, научные/культурные бонусы и дипломатия не реализовывались.
Коммитов и публикации не было.

## Причины подвисания и устранение

1. **Неограниченное ожидание устаревшей очереди.**
   В [тестах проектов](../../tests/campaignProjects.test.ts) и
   [сгенерированной кампании](../../tests/galaxyCampaign.test.ts) циклы
   ожидали заполнения `session.production.completed`. В Conquest Н07 этот
   список всегда пуст: очередь перенесена в `colonyOutput.production`.
   Условие не могло выполниться независимо от исправности самой игры.
   Assertions переведены на актуальную модель, все ожидания ресурсов/выпуска
   в этих сценариях ограничены числом раундов с явным отказом.
   Добавлена регрессия, подтверждающая конечный отказ недостижимого условия.
2. **Timeout Vitest не является прерывателем синхронного цикла.**
   Увеличение `testTimeout` не исправляет такую ошибку.
   Повторные проверки запускались с внешним wall-clock `timeout`,
   отдельным от ограничений игровых окон и тактических секунд.
   Итоговый полный suite завершился самостоятельно за51.22с.
3. **Полная baseline-матрица тяжёлая и поздно публикует результат.**
   Она выполняет54 обычные партии до200 окон и4 boundary, затем repeat и
   checkpoint-continuation для каждого входа. JSON пишется лишь после
   всей матрицы. `timeout200` — нормальный предел игровых окон,
   не200 секунд и не обязательно зависание.
   Прежний незавершённый запуск не засчитан. Вместо повторного длительного
   запуска отдельно измерены18 шестимировых вариантов под внешним лимитом60с.
   Полная матрица после Н07 не объявляется измеренной.

Семь прежних demographic failures также устранены:
фикстуры уменьшают назначения вместе с P, бюджетные oracles используют
новые тарифы; диагностический отказ автооснования по кредитам проверяется
при цене выше доступного после нового дохода остатка.
Позднее переполнение добычи теперь действительно достигает mining-фазы,
а не отказывает раньше из-за увеличенного дохода населения.

## Реализованный контракт

[campaignOutput](../../src/domain/campaignOutput.ts) задаёт назначения,
промышленный выпуск, научный/культурный резервы, quote/refund и FIFO.
[Conquest](../../src/domain/conquest.ts) владеет состоянием, правами,
транзакцией, проекцией и квитанцией.

- Одна единица P —1000 жителей и один доступный абстрактный работник.
  Назначения по трём отраслям не превышают P.
- Default:3 credits/1 mineral дохода на P, содержание1 credit/P и1/ship;
  один point/worker. Выпуск читается до роста текущего хода.
- Полный prepay; требуемые очки=`ceil(credits/10)` по default snapshot.
  `productionCreditsPerPoint` теперь явно передаётся из rules в quote,
  validator, UI, AI и baseline, а не игнорируется.
- Один FIFO-head на свою колонию за own-end, без spillover.
  Заказ за head имеет нулевой прогресс; повреждённый save не исправляется.
  Ноль промышленности означает paused, а не фиктивный «1 ход».
  Forecast возвращает число оставшихся own-turn либо null при paused.
- Refund обеих валют — точная вниз округлённая доля неприменённых очков,
  с BigInt для произведений; overflow отклоняет отмену атомарно.
- Наука/культура копятся с cap10×P стороны; уже накопленное выше нового
  cap не удаляется и не растёт. Наука пока не ускоряет временное дерево.
- Убыль источника колонистов сокращает назначения пропорциональным полом
  с остатками industry→research→culture. Capture обнуляет назначения,
  удаляет очередь прежнего владельца без refund, не передаёт его резерв.
- AI сохраняет turnReceipt и сообщения сокращений из всего пакета.
  UI показывает действительные rates/прогресс/срок/paused/резервы;
  мобильные44px controls больше не пересекаются по вертикали.
- Актуальные форматы: save8/rules5, rules snapshot3/rules3, baseline4.
  Иные версии явно отклоняются, без migration/fallback.

3 существующих расписания,6 миров. Все завершены без executor error;
repeat и checkpoint/save-continuation совпали. Полный JSON сохранён
как диагностический результат сессии, не внесён в игровой формат.

## Настоящий браузер

Использован настоящий Phaser через Vite и встроенный браузер.
Проверены фактические `innerWidth/innerHeight` и
`canvas.getBoundingClientRect()`:1280×720 и390×844, начало(0,0).
Размер screenshot-preview и номинальная host-настройка не подменяют CSS-замер.
На проверенной desktop-странице текст≥14 CSS px, controls≥44×44,
в worker-view mobile нет выхода текста за viewport или малых controls.
Есть resize в обе стороны без изменения игрового состояния.

Оплаченный сценарий на новой сгенерированной карте6:

1. Стартовые100/50, обычные own-end обеих сторон для финансирования;
   собственный blueprint каждой стороны сохранён настоящими командами.
2. Назначения3 industry/2 research/1 culture; два заказа с ценой21 points.
   На окне5 каждый имеет progress3/21, резервы2/1.
3. Настоящее сохранение8/5 мышью в localStorage, page reload и явная load:
   полный state равен сохранённому; следующий end совпал с независимым
   domain-oracle, включая казны/прогресс/резервы.
4. На mobile мышью industry−/+ изменили назначение и вернули исходное,
   не меняя P. Завершение обоих заказов к окну17 полностью совпало
   с непрерывной веткой; резервы14/7 у каждой стороны.
5. Blue размещён мышью, red — событием настоящего control.
   Обе стороны получили корабль с полным баком3.
   Обычный оплаченный перелёт blue привёл к настоящему бою на окне19:
   red победил, blue#1 уничтожен. Полный state совпал с battle oracle.
6. После боя записан actual save на окне20; второй page reload/load
   восстановил полный state/operations/reserves. Следующий red-end→21
   совпал с независимым oracle целиком.

Подготовка blueprint/назначений/перелёта выполнялась командами сцены,
часть controls — Phaser pointer-событиями, часть — mouse input.
Прямых подстановок казны, владения, заказов или кораблей в игровое состояние
не было. Это не полный mouse-only E2E и не physical-touch/quota/FPS benchmark.
Начальные пустые localStorage/sessionStorage восстановлены удалением
только тестовых ключей. Временный сервер остановлен; тестовая вкладка
переведена на about:blank, фоновых проверок не оставлено.
