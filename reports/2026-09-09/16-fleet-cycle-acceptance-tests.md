## Изменения и решения

- [tests/campaignScene.test.ts](../../tests/campaignScene.test.ts): +303/−1 строка. Добавлен тип StoragePort в существующий импорт и один it.each с двумя новыми тестами preset/library; прежние 145 сценовых тестов сохранены.
- В каждом варианте обе стороны обычными кнопками основывают соседнюю колонию, получают отказ покупки, копят 380/190 к ходу 29 и оплачивают по два fighter за 370/22. Library читает сохранённый fighter из временного хранилища v2 через настоящий ShipDesignManager и ProductionCatalog.
- Проверяются FIFO без переноса лишнего прогресса, IDs заказов/кораблей 1–4, порядок completed 1/3/2/4, размещение, группы 1=[1,2] и 2=[3,4], сохранность оплаченных проектов после refresh и на каждом шаге.
- Каждая группа выполняет три перелёта до 0/0; отправка отклоняется без изменений. Заправка первого за 15/6 даёт 3/0 и повторный атомарный отказ; заправка второго за 15/6 позволяет отправиться с 2/2. Четвёртый перелёт возвращает группы домой, затем расформирование оставляет четыре доступных одиночных корабля с топливом 2.
- Точные проверки казны/хода: готовность к ходу 45 при 170/248 каждой стороне; после возврата ход 55 и 240/286; после расформирования и двух завершающих ходов ход 57 и 260/296. Это фиксирует текущие коэффициенты, не оценку баланса.
- Проверяются payload, expectedTurn, неизменность входного состояния, принятие только успешного результата, чужая проекция (кроме публичной смены хода), собственные списки, отсутствие групп на endpoints в пути и появление после arrival, отказ действий неактивной стороны, отсутствие повторной оплаты через старые callbacks.
- Настоящие domain/catalog/repository не подменяются: spies только наблюдают вызовы. Подменены Phaser и временный StoragePort; состояние сцены только читается. Проверяются отсутствие setItem и повторных чтений каталога при маршрутах, сохранность содержимого storage, reset/cancel/reentry, инертность старых callbacks и освобождение панелей/ESC/global storage.

### Настоящий Phaser

В активной видимой вкладке начата новая партия. Все игровые действия выполнены событиями существующих кнопок: никаких прямых executeSessionCommand или записей в campaign/treasuries/ships/turn. Для preset стартовая покупка отклонена, накопление/четыре оплаченных заказа/FIFO/размещение и группы выполнены обычными ходами. На turn47 две группы; после трёх переходов каждой — turn53/четыре пустых бака. Отправки при0/0 и3/0 проверены сравнением полного сериализованного state до/после: без изменений. Два refuel по15/6 у каждой стороны, четвёртый перелёт домой, disband и проверка доступности single send. Конец turn57: ships1/2sol и3/4vega,fuel2;groups{lastFleetId2,items[]}; казны260/296 обеих сторон. Проекты совпали с оплаченными snapshot; real localStorage совпал с исходным.

После reset отдельно повторён **library**. Настоящий ShipDesignManager.saveDesign сохранил созданный fighter во временный Map-backed StoragePort. Только на время синхронного блока подготовки каталога global localStorage заменён read-only портом (запись бросает исключение); исходный descriptor восстановлен в finally. Каталог прочитан3 раза, временная сохранённая строка не изменена. Все четыре оплаченных/размещённых проекта точно равны сохранённому. После восстановления настоящего localStorage последующие маршруты/заправка не перечитывали каталог и не меняли пользовательское хранилище. Достигнут тот же turn57/ресурсы/ships/fuel/пустые группы; оба атомарных отказа проверены отдельно для blue и red.

Для library проверены cancel reset (четыре корабля остаются), confirm reset (новая партия), удаление временных диагностических снимков. Выход освобождает campaign/0children/0ESC, новый вход — turn1/0ships/fleets{0,[]},1panel/1ESC/1canvas. Ручной game.step не применялся.

Это **программный браузерный smoke**, не mouse E2E. Новой вёрстки нет, повторные screenshots не требовались. Попытка физического Escape через отдельные browser keydown/keyup в видимой вкладке с enabled keyboard не сняла pending. Событие Phaser keydown-ESC корректно отменило pending, затем закрыло маршруты в группы. Причина доставки физического ввода не установлена; ограничение из S3.17 остаётся, не заявляется исправление или физическая E2E-приёмка клавиатуры.
