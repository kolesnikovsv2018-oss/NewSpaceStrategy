# 02 — S3.4: экономика и завершение хода на карте

- Дата: 2026-09-09
- Пункт плана: S3.4
- Статус: выполнено; S3 целиком открыт

## Цель и границы

Подключить чистый CampaignSession к карте: показывать ресурсы/доход наблюдаемой стороны, номер хода и активную сторону, завершать ход через проверенную команду. Переключение наблюдения не должно давать право действовать за неактивную сторону. Проверить отказы, устаревшие callbacks, подтверждения и cleanup.

Производство/очереди, расходы/содержание, флоты/перелёты, бой, AI и сохранение не входят. Правила экономики S3.3 не менялись. [План](../2026-09-07/plan.md), [контракты стратегии](../../docs/CAMPAIGN.md).

## Изменения и решения

- [MainScene](../../src/scenes/MainScene.ts) хранит CampaignSession вместо CampaignState. Начало/сброс создают turn1, blue/Сол и две казны100/50. Все игровые команды отправляются через executeSessionCommand; прямого обхода очередности через executeCampaignCommand нет. Состояние заменяется только при ok.
- [CampaignPanel](../../src/ui/CampaignPanel.ts) получает только CampaignSessionView. Отображает собственные кредиты/минералы, ожидаемый доход, публичные turn/activeFactionId. Полные казны/скрытая модель панели не передаются. Добавлена кнопка campaign-end-turn.
- После endTurn наблюдаемая сторона сохраняется, чтобы видеть начисление; подсказка предлагает переключиться для управления следующей стороной. «Сменить сторону · локально» меняет только проекцию, сохраняет выбранную систему и очищает сообщение/ошибку. Это локальное управление обеими сторонами, не AI/multiplayer.
- Кнопки действий неактивной стороны остаются доступны для объяснения отказа моделью. UI не дублирует правила очередности/стоимости/доступности. Ошибки выводятся без частичного принятия результата.
- Callback захватывает показанные expectedTurn/factionId/systemId при создании панели. Старые обработчики блокируются disposed-защитой после redraw/reset/restart. Номер хода не считывается из нового состояния поздним callback; домен отдельно отклоняет устаревший expectedTurn.
- Подтверждения блокируют также endTurn. ESC/отмена не теряют партию; подтверждённый сброс восстанавливает всю экономику, выход освобождает сессию/панель и снимает ESC. Панель пересоздаётся по действиям, не каждый кадр.
- [campaignScene.test.ts](../../tests/campaignScene.test.ts): прежние сценарии адаптированы к сессии, добавлено 10; всего 21 сценовый контракт с fake Phaser. Зависимости, lock-файл, схемы домена и корабельная библиотека не изменены этим шагом. Накопленные локальные изменения сохранены, коммит/публикация не выполнялись.

### Настоящий Phaser

После прерванного ожидания браузерного инструмента проверка выполнена заново короткими вызовами. Страница отвечала, вкладка активна; предыдущая надпись ожидания сама по себе не считалась подтверждением результата. В завершающем прогоне ручной game.step не потребовался; импорт использовал точный URL загруженного main-модуля, не создавая вторую игру.

1. **Мышь:** вход кнопкой «Галактика», выбор Эдема, завершение хода. Подтверждены selectedId=eden и переход turn1→2; у blue после второй колонии120 кредитов/60 минералов, наблюдение осталось blue.
2. **Программные события настоящих кнопок:** отказ колонизации неизвестной цели без изменения сессии; разведка/колонизация; ожидаемый доход20/10 при неизменном балансе100/50 до endTurn. Повторный endTurn неактивной blue отклонён без изменений.
3. **Другая сторона:** переключение очищает сообщение и скрывает Эдем, казна red100/50; red разведывает/колонизирует Узел и завершает ход, получает120/60. Повтор сохранённого callback не начисляет ещё раз. Возврат blue скрывает сведения Узла.
4. **Диагностическая подстановка:** временно выставлены resource cap, изменённый без redraw номер хода и MAX_TURN. Сообщения overflow/stale/terminal показаны, ошибочные команды не начисляют доход; исходный снимок восстановлен в finally. Снимок localStorage до/после этого диагностического сценария совпал. Это проверка граничных состояний, не достижение лимитов обычной игрой.
5. **Подтверждения:** фоновые команды, включая endTurn, без input. ESC отменяет reset без потери turn3; подтверждение возвращает turn1/blue/Сол/100/50. Старый callback после reset инертен. Выход освобождает сессию, снимает ESC; повторный вход даёт одну панель/один обработчик ESC/один canvas.
6. **Отрисовка:** проверенные сообщения, максимальные числа и подтверждение внутри логических1280×720; итоговый screenshot осмотрен. Карта оставлена с новой партией.

Это частично мышиная, преимущественно программная проверка настоящего Phaser, не полный пользовательский E2E, не FPS/баланс-тест. Fake-Phaser регрессии перечислены отдельно. Адаптивность всех экранов/мобильный ввод и сохранение кампании не проверялись; сохранения кампании пока нет.
