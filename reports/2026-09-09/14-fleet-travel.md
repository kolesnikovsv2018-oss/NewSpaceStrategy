# 14 — Модель группового перелёта

- Дата: 2026-09-09
- Пункт плана: S3.16
- Статус: выполнено

## Цель и границы

Отправка целой группы между соседними собственными колониями, атомарное топливо каждого участника и совместное прибытие. Без UI отправки группы/нового списка маршрутов, редактирования состава, групповой заправки, снабжения/содержания, стратегического боя, AI и save. Ёмкость/цены топлива, тактическая скорость и корабельные формулы не менялись.

## Изменения и решения

- [campaignSession.ts](../../src/domain/campaignSession.ts): строгий sendFleet с kind/factionId/expectedTurn/systemId/fleetId/destinationId. Общие state/command/stale/active, собственные endpoints/смежность/точный ID группы и топливо всех участников проверяются до записи. Успех каждому fuel−1 и отдельный transit; казна/turn/ID/проект/состав неизменны. При нехватке любого бака нет частичного списания/вылета.
- Маршрут только в существующих ship.transit, без второго group.transit. Сессия требует одинаковые source/side всех участников и одинаковые target/remaining1 у всех либо отсутствие transit у всех. Частичный вылет/прибытие/разные даже валидные маршруты — INVALID_STATE. Старые стационарные state S3.15 совместимы без default/миграции; отсутствие fleets/ships/fuel по-прежнему ошибка.
- Первый успешный own endTurn одновременно переносит group.systemId и всех участников, удаляет ship.transit, сохраняет membership/порядок/ID/snapshot и остатки топлива. Атомарно с доходом/FIFO/free trips. Чужой ход не двигает группу; отказ ресурса/turn не меняет никаких прибытий и не возвращает топливо предыдущей успешной команды.
- FLEET_IN_TRANSIT запрещает повтор send/redirect/disband. В пути member single send/refuel/create получают прежний SHIP_IN_TRANSIT. После arrival операции из новой колонии и в свою очередь. Стоящая группа допускает индивидуальный refuel, но single send по-прежнему требует disband.
- [campaignFleets.ts](../../src/domain/campaignFleets.ts): getFleetTransit возвращает detached маршрут из проверенных участников, isFleetAtColony исключает travelling группу из обоих endpoints. Это селекторы validated state/view, не самостоятельная командная граница. Общие лимиты20/100 учитывают путешествующих; group/production ID caps не блокируют отправку, MAX_TURN блокирует arrival.
- [MainScene](../../src/scenes/MainScene.ts) и [FleetPanel](../../src/ui/FleetPanel.ts) используют новый селектор присутствия для списков/страниц; есть сообщение sendFleet и явная подпись API-only. Существующий TravelPanel показывает участников как отдельные transit; отдельный список/кнопка группового маршрута не добавлены.
- [campaignFleetTravel.test.ts](../../tests/campaignFleetTravel.test.ts):66 новых регрессий. [campaignScene.test.ts](../../tests/campaignScene.test.ts):3 проверки существующего UI при API-отправке. Новых зависимостей/lockfile нет, ShipDesign v2/библиотека/боевой runtime не изменялись.

### Браузерный сценарий

Прежняя вкладка после HMR оказалась скрытой в LoadingScene; открыта новая видимая вкладка. Ручной game.step не использован. Точный URL main-модуля взят из scripts, второй Game не создавался.

Существующими кнопками программно обе стороны основали соседние колонии, накопили доход, оплатили по два истребителя185/11, завершили FIFO. На turn45 blue размещает ID1/2 и создаёт группу1 через интерфейс. API sendFleet Сол→Эдем даёт fuel2/2, казна неизменна. В источнике count «колонии0/стороны1», disband отключён; API disband отклоняется FLEET_IN_TRANSIT без изменения state. В целевой колонии группа не видна до own endTurn; после него группа1 и оба участника в Эдеме.

На turn46 red размещает ID3/4, создаёт группу2 и через API летит Вега→Узел. На turn47 группа2 и оба участника прибыли с fuel2; синие не переместились. Проекты всех четырёх ships совпали с оплаченными snapshot.

Blue возвращается Эдем→Сол и снова Сол→Эдем через обычные свои endTurn: к turn51 оба бака0. Кнопка refuel заполняет одного; sendFleet при3/0 возвращает INSUFFICIENT_FUEL, весь state неизменен. После refuel второго успешная отправка даёт2/2; казна blue200/266 после двух полных заправок по15/6. На следующем own endTurn группа1 с прежними ID/составом прибывает в Сол.

Вспомогательный browser checker первоначально ошибочно трактовал сохранённое сообщение отказа после навигационной стрелки как новый отказ операции; проверка продолжена с текущей выбранной страницей, отказ3/0 и успех2/2 подтверждены повторно. Игрового изменения для этого не требовалось.

LocalStorage/проекты не менялись. Reset даёт turn1/0ships/fleets{0,[]}; выход освобождает сессию/0children/0ESC; повторный вход —1panel/1ESC/1canvas и новая чистая партия. Временные снимки для проверки удалены.

Это **программный browser smoke, не mouse E2E**: существующие кнопки вызваны событиями, sendFleet/disband-in-flight через API. Игровые state/казны/корабли не подставлялись. Предельные лимиты/несогласованные маршруты/overflow проверены тестами, не браузерными инъекциями. Новая вёрстка отсутствующего UI отправки, FPS и баланс партии не заявляются проверенными.
