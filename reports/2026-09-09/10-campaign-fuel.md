# 10 — Стратегическое топливо одиночного корабля

- Дата: 2026-09-09
- Пункт плана: S3.12
- Статус: выполнено в модельных границах; UI заправки — следующий шаг

## Цель и границы

Добавить чистую проверяемую модель топлива для уже существующего sendShip, не использовать тактическую энергию/скорость/массу/груз и не менять ShipDesign v2. Полная заправка — команда сессии, не новое окно UI. Снабжение/содержание/группировка флотов, бой/AI/save не входят, весь S3 остаётся открытым.

## Изменения и решения

- [campaignShips.ts](../../src/domain/campaignShips.ts): обязательный целый fuel0..3, константы ёмкости3/расхода1 и цены5credits/2minerals за единицу, чистый strict getRefuelQuote. Ёмкость одинаковая у всех корпусов — минимальный предварительный баланс, не производная батареи или гарантированный баланс партии.
- [campaignSession.ts](../../src/domain/campaignSession.ts): deploy добавляет полный бак3 без дополнительного списания (начальный комплект постройки). send проверяет fuel после прежних own/route guards и атомарно списывает1 вместе с созданием transit. Прибытие/ожидание/endTurn не расходуют, не возвращают и не пополняют запас. Failed endTurn не откатывает уже выполненный send.
- refuelShip принимает только factionId/expectedTurn/systemId/shipId. Нужны активная сторона, своя колония, собственный стоящий ID именно в ней. Полный бак — FUEL_FULL; недостаток любого ресурса — INSUFFICIENT_RESOURCES без частичного списания/наполнения. Успех списывает оба ресурса и заполняет бак, не меняет turn/ID/проект/производство/позицию. Empty send — INSUFFICIENT_FUEL. Лишние fuel/cost/amount/capacity запрещены в командах.
- Снимки остаются независимыми, view содержит только own fuel. Старые записи ships без fuel теперь INVALID_STATE без default/автозаправки/миграции; пустые партии валидны. Production-записи и библиотека v2 без топлива, формат проекта/тактическое состояние неизменны. После HMR старой схемы требуется новая партия.
- [TravelPanel](../../src/ui/TravelPanel.ts) и [CampaignPanel](../../src/ui/CampaignPanel.ts): только исправлены подписи расхода и отсутствующего UI заправки, константы взяты из домена. [MainScene](../../src/scenes/MainScene.ts) различает сообщение refuel, но кнопки/API callback для пользователя ещё нет. Generic callback карты не расширен без payload.
- [campaignFuel.test.ts](../../tests/campaignFuel.test.ts):55 новых чистых регрессий. [campaignScene.test.ts](../../tests/campaignScene.test.ts):1 новая на отказ пустого бака/честные подписи. Прежние [deployment](../../tests/campaignShips.test.ts) и [travel](../../tests/campaignTravel.test.ts) фикстуры явно дополнены fuel, полные ожидания отражают расход. В тесте пересечения ID удалено случайное внесение fuel в production-запись, чтобы он по-прежнему проверял именно ID-инвариант.
- Зависимости/lockfile не менялись; рабочее дерево в начале было чистым. Коммитов/публикации не выполнялось. [План](../2026-09-07/plan.md), [правила кампании](../../docs/CAMPAIGN.md) и [README](../../README.md) актуализированы; исторические отчёты не переписаны.

Не полный mouse E2E: заправка проверена через API, большая часть сценария программными событиями. Игровое state/ресурсы/ownership/корабли не подставлялись. Тактический бой/верфь/перезагрузка библиотеки/FPS/баланс не перепроверялись браузером. Старая общая вкладка была скрыта и оставалась в LoadingScene; smoke проведён в новой видимой вкладке, без ручного game.step и изменения приложения ради проверки.
