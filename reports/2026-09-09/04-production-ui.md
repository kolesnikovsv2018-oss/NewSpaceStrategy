# 04 — Интерфейс производства своей колонии

- Дата: 2026-09-09
- Пункт [плана](../2026-09-07/plan.md): S3.6
- Статус: выполнено в ограниченных границах интерфейса заказов

## Цель и границы

Подключить принятую модель S3.5 к карте: выбор проекта, цена/срок, постановка, собственная очередь/прогресс/готовность и отмена с возвратом. Не писать корабельную библиотеку; сохранить атомарные session-команды, независимые снимки, приватность проекции и защиту от старых callbacks. Размещение готовых кораблей, флоты, перелёты, содержание, AI, бой и save не входят.

## Изменения и решения

- [ProductionCatalog](../../src/utils/ProductionCatalog.ts): семь существующих пресетов и сохранённые проекты через read-only ShipDesignManager.load. Независимые копии; flight-валидация и quote, неполные draft с причиной без разрешения заказа. Ошибка библиотеки явно показана, пресеты доступны, repair/save нет. Чтение лениво при первом открытии и по «Обновить», не каждый redraw.
- [ProductionPanel](../../src/ui/ProductionPanel.ts): своя выбранная колония, последовательный выбор проекта с источником/номером, цена/срок, три строки очереди, статус/оставшиеся ходы, точный возврат на кнопке немедленной отмены. Готовые записи — по одной на страницу. Чужая/неизвестная система не имеет controls; панель получает только SessionView, не полный state.
- [CampaignPanel](../../src/ui/CampaignPanel.ts): вкладка производства вместо левой карты, правая экономика остаётся доступна. Родитель уничтожает дочернюю панель. Для выбора иной системы вернуться на карту.
- [MainScene](../../src/scenes/MainScene.ts): отдельные payload-callbacks, захваченные factionId/systemId/expectedTurn/копия design, cancel с orderId. При успехе принимает result.state, при отказе показывает сообщение без подмены состояния. Старые callbacks после любого redraw инертны; новое нажатие в том же ходу остаётся новым оплачиваемым заказом.
- Pending блокирует производственные действия и навигацию. ESC отменяет подтверждение, затем закрывает производство, затем на карте запрашивает меню. Reset/shutdown освобождают каталог/выбор/страницу/дочернюю панель.
- Браузер выявил дефект первоначального ограничения текста: wordWrap+maxLines скрывал длинное имя целиком после большого ID. Исправлено обрезкой по реальной ширине текста с многоточием; регрессия использует синтетическую ширину, фактический шрифт проверен отдельно. Имя исходного проекта не меняется.
- Пресеты и локальная библиотека общие обеим сторонам; это не исследованные технологии и не фракционное хранилище. Срок относится к самому заказу, без ожидания предыдущих. Формулы корабля/цены, стартовые средства и доход не изменялись.

### Настоящий браузер

- Короткие завершённые вызовы в активной вкладке, без ручного game.step. Открытие производства, попытка заказа без средств, успешный заказ и отмена проверены мышью; остальные сценарии преимущественно программными событиями настоящих Phaser-кнопок.
- Пустая библиотека: семь пресетов. Первый истребитель стоит185 кредитов/11 минералов/4 собственных хода. Стартовая попытка отклонена. После18 обычных endTurn со сменой наблюдения получены turn19 и190 кредитов blue; заказ списал до5/84. Средства в этом сценарии не подставлялись.
- После собственного endTurn показано1/4, осталось3, возврат138/8. Отмена неактивной стороной отклонена; чужой наблюдатель не видит заказ/controls Сола. После хода red мышью выполнена отмена:0 заказов, blue153 кредита.
- После накопления обычными ходами новый callback вызван дважды: ровно один заказ. После четырёх собственных завершений хода —0 pending/1 completed, отображается `#2 Истребитель-1`, turn36. Снимок экрана осмотрен.
- Отдельная **диагностическая подстановка**: временный StoragePort в памяти с валидным длинным именем из80 букв и неполным проектом, три заказа с большими ID, две готовые записи и большой номер хода. Записей storage0; неполный проект показывает причину, enqueue без input. Пагинация2/2 работает. После исправления ширины видимы ID и часть имени с многоточием (431/430/733 px); проверенные тексты не выходят за левую панель/1280×720. Это не обычный пользовательский путь создания такого состояния.
- Подтверждение блокирует вкладку/refresh/enqueue/cancel/страницы; ESC отменяет без потери очереди, следующий ESC возвращает карту. Reset очищает очередь/каталог/ход; сохранённый старый callback не действует. Повторные переключения вкладки не оставили объектов. После выхода children0/ESC0/state освобождён; повторный вход turn1, пустое производство, одна панель/ESC-handler/canvas.
- Сравнения localStorage до/после сценариев совпали. Диагностическая партия сброшена; оставлена новая партия. HMR между правками вернул меню, поэтому проверка исправленного текста повторена в новом экземпляре игры. Ранее в журнале вкладки было пустое событие pageError без текста; причины по нему не устанавливались, завершающие сценарии прошли. Проверка не является полным mouse E2E, загрузочным/FPS-тестом или испытанием тактического боя.
