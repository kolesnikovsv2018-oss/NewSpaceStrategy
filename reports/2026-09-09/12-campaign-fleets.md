# 12 — Стационарные группы кораблей

- Дата: 2026-09-09
- Пункт плана: S3.14
- Статус: выполнено

## Цель и границы

Чистая модель объединения своих стоящих кораблей одной колонии с атомарным созданием/расформированием, строгими командами и независимыми проекциями. Не входят интерфейс групп, групповой перелёт, изменение состава, снабжение/содержание, бой кампании, AI и сохранение. Баланс топлива/скорость не менялись.

## Изменения и решения

- [campaignFleets.ts](../../src/domain/campaignFleets.ts): CampaignFleet{id,factionId,systemId,shipIds},2–10 участников, до20 групп на сторону. Только ссылки на ship ID, без копий проекта/топлива/runtime и без дублирующего fleetId на корабле. Один ship максимум в одной группе.
- [campaignSession.ts](../../src/domain/campaignSession.ts): обязательное fleets{lastFleetId,items}, strict createFleet/disbandFleet, cross-state проверки существования/принадлежности/колонии/стационарности. Групповые ID1..1e9 выдаются отдельно от производственных, items возрастают; расформирование не возвращает ID. Порядок участников сохраняется.
- Операции бесплатны/без смены хода и не меняют ships/казны/production. Все проверки до записи, успех глубоко отделён, отказ без state. Общие expectedTurn/active/own проверки сохранены; дополнительные SHIP_IN_FLEET/FLEET_LIMIT/FLEET_ID_LIMIT/FLEET_NOT_FOUND.
- Одиночная отправка участника запрещена до расформирования; одиночная refuel разрешена по прежней цене и не меняет членство. Свободные корабли/прибытие/производство работают прежним образом. EndTurn не перемещает группы.
- Own SessionView.fleets не содержит чужих групп/глобального счётчика и не разделяет массивы с исходной сессией. Это не multiplayer-авторизация. Старые runtime-сессии без fleets отклоняются без default/миграции, после HMR нужна новая партия. ShipDesign v2/localStorage не менялись.
- [MainScene](../../src/scenes/MainScene.ts) получила сообщения новых команд, не новый UI. Текущая TravelPanel показывает участников среди обычных кораблей и доменный отказ send.
- [campaignFleets.test.ts](../../tests/campaignFleets.test.ts):94 новые доменные проверки. [campaignScene.test.ts](../../tests/campaignScene.test.ts):1 новая проверка send/refuel/reset с группой. [campaignSession.test.ts](../../tests/campaignSession.test.ts): обновлены полные ожидания стартовой сессии/ключей проекции.

### Браузерный сценарий

Новая партия в настоящем Phaser, видимая вкладка. Программные события существующих кнопок: blue разведывает/колонизирует Эдем, получает обычный доход, оплачивает два истребителя по185/11, завершает FIFO и размещает оба к turn45. Казна170/248, корабли ID1/2 в Соле с полными баками. Игровой state/казны/корабли не подставлялись.

Через API сцены createFleet([2,1]) создаёт группу ID1. Событие кнопки send показывает «сначала расформируйте её», полный state неизменен. Disband через API освобождает корабли, счётчик сохраняется. Одиночный корабль кнопками летит Сол→Эдем→Сол, после обычных endTurn на turn49 имеет fuel1. Повторная createFleet([1,2]) выдаёт ID2; refuel через существующую кнопку меняет казну210/268→200/264 и бак1→3, группа неизменна. Оплаченные проекты и снимок localStorage совпадают с исходными.

Проекция blue содержит группу2, red — пустой список. Reset восстанавливает turn1/0ships/fleets{0,[]}; выход освобождает state,0children/0ESC; повторный вход даёт1panel/1ESC/1canvas и чистую новую партию. Временная диагностическая запись для сравнения снимков удалена.

Это программный браузерный smoke, **не mouse E2E**: существующие кнопки вызваны событиями, групповые операции напрямую через API, ручной game.step не использован. Красная группировка/предельные состояния проверены автоматическими тестами, не новым браузерным сценарием. Новый UI не создавался, его вёрстка/hit testing не заявляются. FPS и баланс партии не измерялись.
