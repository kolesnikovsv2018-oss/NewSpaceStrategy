- Дата: 2026-09-09
- Пункт плана: S3.17

## Цель и границы

Подключить отправку выбранной группы к соседней своей колонии, просмотр собственных групп в пути и прибытия по правилам S3.16. Без изменения состава/групповой заправки/снабжения/содержания/боевого runtime/AI/save и баланса. S3 целиком остаётся открытым.

## Изменения и решения

- [FleetTravelPanel](../../src/ui/FleetTravelPanel.ts) — отдельный экран внутри [FleetPanel](../../src/ui/FleetPanel.ts), Производство → Группы → Маршруты. Не уплотняет существующий выбор состава; кнопка «← Группы» возвращает к нему. Панели уничтожаются каскадно.
- Только SessionView: собственные группы выбранной колонии через isFleetAtColony, соседние explored own цели из projected lanes, минимальный бак/число пустых участников, расход1 каждого, отправка. Нижний список — все own groups с getFleetTransit, по одной записи/странице: ID/число участников/source→target/1 свой ход. Общие лимиты20/100 учитывают летящих.
- Нет группы/цели/pending — disabled; empty fuel/inactive остаются доступными для настоящего доменного отказа. UI не вычисляет исход команды, не списывает ресурсы и не создаёт маршрут. Согласованность состава и единственный маршрут в ship.transit не менялись.
- [MainScene](../../src/scenes/MainScene.ts) захватывает side/system/turn, panel — показанные fleetId/destinationId. Новые fleetTravelOpen/fleetDestinationIndex/fleetTransitPage содержат только UI-выбор; fleetPage общий со списком групп. После успеха send выбран новый маршрут, сброшены цель/страница участника; render ограничивает group/transit pages после вылета/прибытия.
- Toggle routes очищает draft состава и маршрутные страницы, сохраняет выбранную группу. Выбор другой группы сбрасывает цель. Смена стороны/колонии/карты/одиночных перелётов/reset/shutdown сбрасывает новый UI-state. Pending сохраняет выбор при отмене, блокирует controls; disposed защищает от старых callbacks после redraw.
- ESC: pending cancel → маршруты в группы → группы в очередь → очередь на карту → запрос меню. После arrival группа целиком видна в цели, больше не в списке маршрутов; в пути местных команд состава нет.
- [CampaignPanel](../../src/ui/CampaignPanel.ts) подписан S3.17; [TravelPanel](../../src/ui/TravelPanel.ts) уточняет, что disband нужен именно для одиночного вылета. Заправка остаётся индивидуальной в прежнем UI. Тексты сокращаются по фактической ширине (цель400px, заголовки590px, остальные745px), данные не меняются.
- [campaignScene.test.ts](../../tests/campaignScene.test.ts):17 новых регрессий; API-сценарий S3.16 сохранён, прежнее ожидание API-only подписи обновлено.
- Стартовое дерево уже содержало staged S3.16. Эти изменения сохранены; индекс не менялся, коммитов/публикации нет. Новых зависимостей/lockfile нет, доменные файлы в S3.17 не редактировались.

### Браузер: обычный оплаченный цикл

В настоящем Phaser начата новая партия, обычными событиями кнопок обе стороны колонизировали соседние системы, накопили доход, оплатили по два истребителя185/11 и завершили FIFO. На turn45 blue разместил ID1/2, создал группу1 и открыл Маршруты. Вёрстка до отправки проверена снимком: кнопки/подписи не перекрываются.

**Мышью** нажата отправка blue Сол→Эдем: fuel2/2, сообщение успеха и общий маршрут. В целевой колонии до own endTurn группы нет, после — группа1 целиком с остатками2. Новая попытка отправки неактивной стороной через событие кнопки получила отказ.

На turn46 red разместил ID3/4, создал группу2 и **мышью** отправил Вега→Узел, fuel2/2; список не раскрыл синюю группу. Следующий own endTurn показал группу2 в Узле. Подготовка/навигация/прибытие программными событиями, не весь цикл мышью.

Blue сделал два следующих перехода обычными кнопками/ходами до0/0 на turn51. Заправлен только первый участник:3/0. **Mouse send** вернул INSUFFICIENT_FUEL, сериализованный state полностью совпал с состоянием до команды. Снимок показал читаемое сообщение и минимум0/3, пустых1/2.

Уточнение подписи одиночного вылета вызвало HMR с новой партией. После него полный оплаченный цикл обеих сторон повторён событиями, без игровых инъекций: три blue перехода→0/0→refuel одного→отказ3/0 без изменений→refuel второго→send2/2→arrival в Сол на turn52. Все четыре размещённых проекта совпали с оплаченными snapshot; localStorage не изменился. SendFleet во всех этих сценариях шёл через новую кнопку, не прямой API.

### Браузер: диагностические пределы и lifecycle

Отдельно сохранён нормальный state и подставлена валидная диагностическая партия:100 own ships,20groups, последняя группа ID1000000000 с10 участниками, в Эдеме две own цели. Показаны20/20,100/100,10 участников и цель2/2. Фактические ширины current/count/destination:300/465/101px. Через события отправлены все20 групп,48 участников в пути, последняя страница20/20 показывает максимальный ID и Эдем→Узел. Это тест пределов UI, не оплаченный игровой цикл.

Во время диагностической проверки вкладка стала hidden. Попытки mouse/ESC/cancel в ней не подтверждают работу ввода; unchanged state при pending **не выдаётся за успешный mouse blocker test**. Отмена и дальнейшие страницы выполнены событиями. Нормальный state восстановлен, localStorage совпал, reset дал turn1/0ships/0groups, временные снимки удалены.

В новой видимой вкладке повторены открытие маршрутов/pending/закрытие обработчиком. Физический Escape средствами интегрированного браузера не снял pending даже после фокуса canvas; причина не установлена, это ограничение проверки. Программный keydown-ESC закрывает маршруты в группы; правила отмены/порядка закреплены Vitest. Это не доказательство физического ESC E2E.

В новой вкладке выход в меню освободил campaign/0children/0ESC; повторный вход дал turn1/0ships/0groups, routeOpen=false, обе новые страницы0,1panel/1ESC/1canvas. Ручной game.step не применялся. Сохранение кампании/FPS/баланс/полная библиотечная групповая цепочка не заявляются проверенными.
