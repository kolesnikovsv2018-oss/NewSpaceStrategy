# 05 — Чистая модель стратегического размещения

- Дата: 2026-09-09
- Пункт [плана](../2026-09-07/plan.md): S3.7
- Статус: выполнено, без UI размещения

## Цель и границы

Разместить собственный готовый проект в стратегическую запись корабля в той же колонии: атомарно, без повторной оплаты/смены хода/дублирования, с независимыми данными и проекцией стороны. Кнопки, группировка флотов, перелёты, содержание, тактический runtime/бой, AI и сохранение кампании не входят.

## Изменения и решения

- [campaignShips.ts](../../src/domain/campaignShips.ts): строгие CampaignShip{id,factionId,systemId,design} и список,100 кораблей на сторону/200 вместе, уникальные ID. Общий flightDesignSchema экспортирован из [production.ts](../../src/domain/production.ts); формулы/валидаторы не изменены, гражданский проект без оружия допустим.
- [campaignSession.ts](../../src/domain/campaignSession.ts): обязательный ships, старт[], cross-state проверка владения колонией, уникальности относительно production и ID≤lastOrderId. Проекция содержит только свои глубоко скопированные ships; полная модель не передаётся вместо view.
- deployProduction принимает factionId/expectedTurn/systemId/orderId. После schema/turn/active проверяет свою колонию, собственный completed именно там и свободное место ships. Успех переносит ровно одну запись, сохраняя ID/проект/колонию; ошибки COMPLETED_NOT_FOUND/SHIP_LIMIT не удаляют completed. Казны/ход/доход/pending/остальные записи не меняются.
- ID заказа становится ID корабля; отдельный счётчик/sourceOrderId не нужен. Счётчик производства остаётся монотонным, ID не переиспользуется. Размещение возможно при MAX_ORDER_ID/MAX_TURN по активной стороне; не увеличивает ни один счётчик. Порядок размещения свободный, не FIFO.
-100 ships и100 pending+completed — независимые ограничения стороны. Размещение освобождает производственное место, но не даёт бесконечного флота; удаления кораблей пока нет. Строгая схема допускает ровно100, операция запрещает добавление при уже100; это разные проверки, не ошибка границы.
- [MainScene](../../src/scenes/MainScene.ts): подготовлено сообщение нового command.kind, чтобы оно не попадало в ответ отмены. Кнопки/общий callback карты не расширялись.
- [campaignSession.test.ts](../../tests/campaignSession.test.ts) адаптирует ожидание начального state и ключей view. [campaignShips.test.ts](../../tests/campaignShips.test.ts) добавляет41 регрессию.

Новые тесты проверяют полный оплаченный цикл enqueue→endTurn→completed→deploy, обе стороны и разные колонии, свободный порядок размещения, повтор в том же/новом ходу, отказ неактивной стороны/неверной колонии/чужого ID/неготового заказа, сохранность казн/хода/ID, независимость вложенных проектов, frozen state/commands и replay. Проверены точные100/200 ships, отдельный лимит противника, переполнение без удаления completed, освобождение production-места и новый ID, MAX_ORDER_ID/MAX_TURN/казны на cap. Строгие схемы отвергают лишний payload, неверные ID/проекты/ships, дубли и пересечение с pending/completed; query бросает ошибку, команда возвращает отказ без state. Чужие корабли скрыты даже после разведки их колонии.

### Браузерный smoke

После HMR запущена новая партия в настоящем Phaser. Программными событиями прежних кнопок проверены открытие производства, цена первого пресета185/11/4, отказ при нехватке средств, обычный endTurn и подтверждённый reset. Итог: turn1, ships[], пустая production, одна campaign-panel/ESC-handler/canvas. localStorage до/после совпал. Вкладка активна, ручные game.step и подстановка готовых кораблей не использовались.

Это только проверка совместимости существующего UI с новой схемой. **Интерфейса размещения нет**, его hit testing/пользовательский цикл не проверялись; доменные тесты не выдаются за браузерные. FPS/масштаб/бой не измерялись.

ID gaps не защищают multiplayer, схема не доказывает историю оплаты произвольного локального state.

Зависимости/lockfile не менялись. Накопленные локальные изменения сохранены; коммит/публикация не выполнялись.
