# 23 — Репозиторий одного слота кампании

- Дата: 2026-09-09
- Пункт [плана](../2026-09-07/plan.md): S3.25
- Статус: выполнено; UI S3.26 и родитель сохранения остаются открыты

## Цель и границы

Добавить отдельный синхронный репозиторий кампании по [контракту](../../docs/CAMPAIGN_SAVE.md), используя готовый кодек S3.24. Без UI, автоматических операций при входе, изменения правил/формата, миграций, удаления слота или вмешательства в библиотеку верфи.

## Изменения и решения

- Новый [CampaignSaveManager](../../src/utils/CampaignSaveManager.ts): ключ `orion_campaign_v1`, необязательный внедряемый `StoragePort`; только type-only импорт общего типа из ShipDesignManager. Конструктор не обращается к storage. По умолчанию `globalThis.localStorage` разрешается лениво внутри try каждой операции: сам getter может бросить.
- `load()` делает один get одного ключа: null → `SAVE_NOT_FOUND`, исключение getter/чтения → `STORAGE_READ_FAILED`, иначе возвращает настоящий decode. Нет записи, fallback, ремонта или создания новой партии.
- `save(unknown)` выполняет encode до доступа к хранилищу. Только успех вызывает один set; `{ok:true}` возвращается после его успешного завершения. Исключение getter/записи → `STORAGE_WRITE_FAILED`. Ошибки кодека передаются без изменения; русские storage-сообщения не раскрывают исходное исключение.
- Экспортированы `CampaignStorageErrorCode`, `CampaignStorageFailure`, `LoadCampaignResult`, `SaveCampaignResult`. Результат загрузки — независимый кандидат, не замена сцены.
- Нет чтения перед save, удаления, rollback-записей, кеша, библиотечных операций. Атомарный set либо throw без изменения прежнего значения — **требование порта**, а не транзакция менеджера. Последняя успешная запись побеждает; CAS/межвкладочная синхронизация не добавлены. Подтверждение перезаписи занятого/повреждённого слота — ответственность будущего UI.
- Добавлены [70 тестов](../../tests/CampaignSaveManager.test.ts). Обновлены [README](../../README.md), [кампания](../../docs/CAMPAIGN.md), [содержание](../../docs/CAMPAIGN_UPKEEP.md), контракт сохранения и план. Исходные схемы, кодек, ShipDesignManager, сцены и зависимости не менялись.

### Продолжение оплаченной партии

Для каждого источника реальная разведка/колонизация/endTurn дают380/190 обеим сторонам на turn29. Заказаны по два fighter: после оплаты10/168. На turn31 сохраняется частично пройденный FIFO с remaining3/4 каждой стороне; новый менеджер загружает его без продвижения. До turn45 восстановленная и непрерывная ветки совпадают, completed1/3/2/4, казны170/248.

Deploy в порядке2/1 и4/3 → группы → send → save/load перед каждым own endTurn. На turn47 обе казны188/258, группы в Эдеме/Узле, четыре корабля с fuel2, очередь/completed пусты. Полные результаты команд, включая квитанции, совпадают; повтор send/stale end отклоняются. Три checkpoints на сценарий дают ровно три get и три set кампании. Библиотечный вариант использует настоящий `ShipDesignManager.saveDesign` во временном порте до цикла; все его ключи затем сохраняются дословно. Это не UI-выбор проекта и не перезагрузка страницы.

### Браузерный smoke

В существующей localhost-странице импортированы только менеджер и модуль сессии. Сцена и игровой entry не переинициализировались. Внедрён временный Map-порт: конструктор0 операций, missing load → SAVE_NOT_FOUND; новая локальная партия проходит реальные команды обеих сторон до turn3 → save → новый менеджер/load → равенство следующего endTurn.

Затем порт намеренно бросает `DOMException` с именем QuotaExceededError до изменения значения: менеджер возвращает STORAGE_WRITE_FAILED, предыдущий слот сохранён. Invalid state отвергается без дополнительной записи. Итого два чтения и две попытки записи (успех+отказ). Sentinel библиотеки и снимок настоящего пользовательского localStorage неизменны.

**Не проверялись:** реальное исчерпание квоты браузера, запись на диск/reload/load, кнопки/подтверждения/lifecycle, полный групповой браузерный цикл, physical ESC и производительность. In-memory порт соблюдает атомарный контракт; тест не доказывает корректность произвольного стороннего порта. Неизменная сборка ожидаема: менеджер ещё не импортируется игровой точкой входа.

## Оставшиеся вопросы и следующий шаг

**Только S3.26:** ручные save/load, подтверждение перезаписи/замены партии, detached candidate без повторного чтения, same-turn callback и reset/shutdown защита, браузер save→reload→load→продолжение. При входе по-прежнему новая партия, без автоопераций. Игрок пока не может сохранить кампанию через интерфейс. Родитель сохранения/AI/победы и весь S3 не закрыты; квота, last-writer-wins и прежний bundle warning остаются ограничениями. Коммиты и публикация не выполнялись.
