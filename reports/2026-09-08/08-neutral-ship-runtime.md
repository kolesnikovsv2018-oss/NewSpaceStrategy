# 08 — Нейтральные движение, энергия и груз

- Дата: 2026-09-08
- Пункт плана: S2.2b, [единый runtime](../2026-09-07/plan.md)
- Статус: ограниченная задача выполнена; S2 целиком остаётся открытым

## Цель и границы

Вынести общие операции из legacy Ship и убрать синтетические компоненты из конструктора DesignedShip. Сохранить старые численные параметры/фабрики/refit и единственное изменяемое состояние. Не менять формат v2, боевые формулы, баланс груза, исполнение service-модулей или кампанию.

## Изменения и решения

- [ShipRuntime](../../src/entities/ShipRuntime.ts) владеет ShipState и копирует initialState со вложенными структурами. Операции consumeEnergy/rechargeEnergy/startMoving/stopMoving/advanceMovement/loadCargoLot/unloadCargo работают с state и запросами характеристик, не читают component-shaped проекции. getState/getCargo возвращают независимые копии.
- [Ship](../../src/entities/Ship.ts) теперь legacy-адаптер поверх ShipRuntime. Старые конструктор, mutable-компоненты, формулы стоимости/массы/скорости, установка оборудования, currentEnergy-accessor и численные пресеты сохранены. Начальная энергия по-прежнему устанавливается setter-ом powerSource из переданного компонента, не остаётся нулевой.
- [withTactics](../../src/entities/TacticalShip.ts) подключает одну реализацию state-accessors/навигации к разным базам. DesignedShip → TacticalShip → ShipRuntime; CombatShip → withTactics(Ship) → Ship → ShipRuntime. Legacy CombatShip остаётся instanceof Ship, проектный корабль — нет. Единственный any ограничен требуемой TypeScript сигнатурой generic mixin-конструктора; данные компонентов и методы не теряют типизацию.
- [DesignedShip](../../src/entities/DesignedShip.ts) создаётся через super(id, name, createDesignState(stats)), без старого Ship и искусственных powerSource/engine/cargoHold. Генерация/ёмкость/расход и статистика читаются из stats, текущая энергия из state. Общая база не создаёт второй агрегированный weapon-state.
- [DesignCompatibilityViews](../../src/legacy/DesignCompatibilityViews.ts) сохраняет выходные имена/числа старой формы. Конфигурация проекций заморожена Object.freeze, currentEnergy остаётся live-accessor с записью. Замена powerSource с той же конфигурацией и новой энергией поддержана; попытка поменять генерацию/ёмкость/другие поля отклоняется, не меняя состояние. Это намеренное ужесточение проектного API: параметры меняются через ShipDesign. Mutable-компоненты настоящего legacy Ship не затронуты.
- [cargoCompatibility](../../src/legacy/cargoCompatibility.ts) явно переводит weight↔mass. Старый loadCargo(weight) остаётся на моделях; нейтральный loadCargoLot принимает только строгий canonical mass. Смешение форматов не угадывается. [FlightShip](../../src/entities/interfaces/FlightShip.ts) задаёт команды для [ShipTestScene](../../src/scenes/ShipTestScene.ts), которая больше не владеет Ship[] и загружает тестовую руду через mass.
- Порядок движения сохранён явно: проект оплачивает шаг до изменения позиции, legacy после. Исправление старой оплаты после движения не подмешано в архитектурную миграцию.

### Браузерная проверка

В настоящем Phaser, на прежней dev-странице с одним canvas, выполнены программные pointerdown существующих кнопок, переходы scene API и конечные ручные game.step. Вкладка скрыта (document.hidden=true); E2E мышью и автоматический RAF не подтверждались. localStorage в этой задаче не изменялся.

- Выбор добытчика → полёт: runtime не является Ship, проекция энергосистемы заморожена, один ESC-обработчик. Движение и энергия обновляются.
- Кнопки загрузки/выгрузки: партия 20 т / 10 м³ отражена в state, совместимом трюме и панели. Скорость снизилась с 98.37678 до 98.25596; после выгрузки груз пуст и скорость восстановлена до 98.37678. Mining остаётся явно неисполняемым.
- Возврат в верфь → дредноут → бой до результата: 3016 мс симуляции, одна потеря, 537.5 суммарного фактического урона, итог показан, очередь событий обработана. Это один случайный исход, не балансировочный тест.
- Повторный запуск без payload: четыре demo-корабля / 16 боевых, один ESC/Space. Пауза не меняет duration, продолжение меняет. Страница возвращена в меню.

Ограничения: production preview отдельно не проверялся, FPS/производительность не измерялись. Числа build не являются доказательством ускорения. Старые публичные scalar setters/consumeEnergy/startMoving/takeDamage не получили полной проверки NaN/отрицательных аргументов; боевые aggregate views остаются mutable. Это отдельный следующий шаг, а не завершённый hardening.

## Оставшиеся вопросы и следующий шаг

Согласовать единицы тактической энергии/мощности/дальности и защитить скалярные runtime-операции от недопустимого ввода. Отдельно определить смысл прежнего getMaxRange: сейчас это оценка без генерации и не стратегическая дальность/топливо. Не менять silently численные legacy-пресеты и не объявлять топливо реализованным.

Служебные действия mining/repair/scanner, сохранение боя, seeded RNG/fixed timestep и стратегический цикл остаются будущими задачами. Родительские пункты S2 не закрыты. Прежние локальные изменения сохранены; коммиты и публикация не выполнялись.
