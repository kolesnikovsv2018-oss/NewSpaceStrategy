## Изменения и решения

- CampaignRunSaveManager.STORAGE_KEY ссылается на CampaignSaveManager.STORAGE_KEY: стабильный `orion_campaign_v1`, не второй слот. Импорт старого класса безопасен без IO, StoragePort импортируется только как тип из ShipDesignManager.
- Конструктор не читает/пишет и не разрешает globalThis.localStorage. Каждая операция получает порт лениво внутри своего try; injected порт не обращается к глобальному getter.
- Load делает один get: null → SAVE_NOT_FOUND; исключение getter/метода → STORAGE_READ_FAILED; остальные значения передаются готовому decodeCampaignRunSave. Успех ровно `{ok:true,run}` с независимым полным run.
- Save принимает unknown, полностью encode до getter, затем один set; `{ok:true}` возвращается только после возврата set. Getter/set exception → STORAGE_WRITE_FAILED, codec-коды передаются без потери UNSUPPORTED_AI_POLICY в типах результатов. Неизвестная policy при encode по прежнему контракту даёт INVALID_STATE, при decode — UNSUPPORTED_AI_POLICY.
- Экспортированы LoadCampaignRunResult/SaveCampaignRunResult; storage failure/code переиспользованы и реэкспортированы из старого менеджера. Русские ошибки фиксированные, без сырых исключений/частичного результата.
- Нет cache/reread/read-before-save/fallback/repair/remove/rollback/подтверждения/автоматической миграционной записи/AI. Load строгого1/1 возвращает local только в памяти; явный save пишет2/1 даже для local. Старый manager остаётся1/1 и отвергает2.
- Атомарный set либо throw без изменения старых bytes — **контракт синхронного порта**, не транзакция менеджера. Два экземпляра используют последний успешный write, без CAS, межвкладочной безопасности или защиты от редактирования локального JSON.

### Оплаченные циклы

Четыре preset/library × local/diagnostic-red-ai сценария используют настоящие каталог/временную библиотеку и команды. Обе стороны реально зарабатывают380/190 к29, оплачивают по2 fighter185/11, получают FIFO31 remaining3/4/3/4, затем completed45 в порядке1/3/2/4 и казны170/248. Реальные deploy/group/send и явные AI-end доводят до47:188/258 каждой стороне, четыре ships fuel2, группы[2,1] в eden и[4,3] в nexus, без transit.

Save → **новый manager → load на31/45/46**, не только JSON round-trip. Полный run/control и результаты всех команд/AI-summary/квитанции равны непрерывной ветке. Библиотечный проект действительно изменён после оплаты, затем библиотечный ключ удалён только из временной Map; команды/AI не читают и не пишут порт. Snapshot/ID/даты/порядок неизменны при разных датах выполнения. Старый checkpoint31 проверен отдельным reader после завершения цикла.

Red получает AI-config **диагностически только после реальной LOCAL-подготовки/отправки**, не через публичную конверсию и не политикой покупки кораблей. Пятый тест — обычный новый AI-run: blue-end→red2 save/newmanager/load без автохода, manual-red запрещён, явный AI→3 равен непрерывному, последующий save/load сохраняет авторизацию и запрет AI-blue.

После уже принятого AI каждой стороны внедрён quota-отказ set: принятый run не откатывается, все предыдущие bytes остаются, старый checkpoint можно прочитать без исполнения/повтора хода.

### Исправления во время проверки

Производственный менеджер не потребовал исправлений. Исправлены два тестовых дефекта: ожидаемые bytes должны брать канонический encode, а не порядок свойств диагностической фикстуры после прямого stringify; намеренно неверный StoragePort требует явного unknown-cast для strict TypeScript. После обоих исправлений повторены полный test, typecheck и build.

## Оставшиеся вопросы и следующий шаг

Браузер, настоящий localStorage, реальная квота/перезагрузка и межвкладочная конкуренция **не проверялись**. Только временные синхронные порты с объявленной атомарностью. Сцена остаётся S3.29/save1/1; нового UI, scheduler, paused/Resume или автохода нет. Не добавлены зависимости, автосохранение, импорты из entry, коммиты или публикация.

Следующий ограниченный **S3.34** — интеграция CampaignRun/режимов/авторизации/нового менеджера в сцену и одноразового scheduler/паузы/Resume/takeover по [контракту](../../docs/CAMPAIGN_CONTROL.md). Наблюдение AI-режима только blue, без red-summary; load red paused, строгий старый1/1 восстанавливается local, новый save2 только явно. Сохранить local helper и защиту pending/source/generation/disposed. Приёмка должна отдельно проверить fake scheduler и настоящий браузерный save/reload. Политика AI, бой и победа не расширяются.
