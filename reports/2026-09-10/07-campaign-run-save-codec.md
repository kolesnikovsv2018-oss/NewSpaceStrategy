- Дата: 2026-09-10
- Пункт плана: [S3.32](../2026-09-07/plan.md)

## Цель и границы

Сериализовать CampaignRun в строгий формат2/1 и явно мигрировать прежний строгий1/1 в local. Без репозитория, IO, UI, scheduling или переключения действующего слота. Интерфейс остаётся S3.29, существующие кнопки используют прежний менеджер/формат1/1.

## Изменения и решения

- Новый [campaignRunSave](../../src/domain/campaignRunSave.ts): encodeCampaignRunSave(unknown) возвращает json, decodeCampaignRunSave(unknown) возвращает независимый run. Отдельная константа CAMPAIGN_RUN_SAVE_SCHEMA_VERSION=2; общие format/rulesVersion1/byte cap импортированы из старого кодека.
- Encode проверяет весь campaignRunSchema, пишет ровно format/schemaVersion/rulesVersion/session/control; версии и метаданные от caller не принимаются. Неверный run/refinement/stringify — INVALID_STATE без частичного результата.
- Decode: тип/UTF-8 размер до parse → JSON → строгая базовая форма/явное наличие session → версия схемы → версия правил → наличие/форма control для поддержанной версии → политика AI → полная модель. Missing session проверяется явно, поскольку z.unknown не гарантирует обязательность ключа.
- 2/1 требует control. Неверный control/mode/лишние поля дают INVALID_SAVE; синтаксически допустимый неизвестный policy ID из1..64 ASCII букв/цифр/дефисов — UNSUPPORTED_AI_POLICY до разбора session. Никакой подмены политики на поддержанную.
- 1/1 запрещает control, после новых guards использует неизменный decodeCampaignSave и добавляет только local. Чтение не записывает обновлённый документ и не выполняет AI; следующий явный encode выдаёт2/1 даже для local. Legacy reader/manager остаётся1/1 и отвергает2 вместо потери назначения стороны.
- Лимит5_000_000 байт UTF-8: проверка до JSON.parse и после stringify, без обрезки/сжатия/ремонта данных. Полные независимые снимки проектов, ID, порядок, FIFO и маршруты сохраняются; библиотека не нужна для восстановления.
- Добавлены [415 основных тестов](../../tests/campaignRunSave.test.ts), [26 fault-only](../../tests/campaignRunSaveFaults.test.ts), [5 интеграционных](../../tests/campaignRunSaveIntegration.test.ts). Существующие исходники, тесты, зависимости, менеджеры и сцены не менялись.
- Актуализированы README, документы кампании/AI/save/control и план; работающий кодек отделён от будущего run-репозитория и интеграции постоянного AI.

### Оплаченные сценарии и точные ограничения

Preset/library × local/диагностический red-AI: настоящие local-команды дают доход380/190 на29, по два оплаченных fighter185/11, FIFO checkpoint31 remaining3/4/3/4→45 с170/248 каждой стороне. После deploy/group/send кодек сохраняет источники/назначения маршрутов и уже потраченное топливо; checkpoints31/45/46 заново декодируются, затем явные run-команды/AI сравниваются с непрерывной веткой целиком.

На47 обе стороны188 кредитов/258 минералов, ID2/1 в Эдеме,4/3 в Узле, у каждого fuel2, группы прибыли. Снимки/ID/даты/порядок не изменились при смене часов2026→2040→2050 и редактировании/удалении только временной библиотеки после оплаты. Новый reader не выполняет команды сам.

Red назначается AI диагностически **после законной local-покупки и отправки** в обеих сравниваемых ветках. Это не публичный local→AI переход и не покупка/отправка политикой. Новый обычный AI-run проверен отдельно без подставленных red-покупок. Здесь реальные JSON round-trips, но не новый manager/localStorage/reload; временный StoragePort используется только для подготовки библиотеки. Размер400 снимков не гарантирует вместимость любого валидного документа или browser quota. Производительность и физический ESC не проверялись.
