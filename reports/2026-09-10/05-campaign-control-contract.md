# 05 — Контракт постоянной компьютерной стороны

- Дата: 2026-09-10
- Пункт плана: [S3.30](../2026-09-07/plan.md)
- Статус: выполнено **только проектирование**

## Цель и границы

Выбрать режимы управления, права сторон, конечный запуск AI, остановку/восстановление и совместимость сохранений до реализации постоянного controller. Работающая игра остаётся S3.29: ручной помощник, save schemaVersion1/rulesVersion1. Исходники, тесты, зависимости и браузерное состояние не менялись.

## Изменения и решения

Создан [CAMPAIGN_CONTROL](../../docs/CAMPAIGN_CONTROL.md) с проверенными исходными фактами, выбранными будущими API, автоматом сцены, save-матрицей и критериями приёмки.

- Режимы: прежний local либо человекblue/компьютерred. Нет AI-AI, AI-blue, новой policy, покупки/отправки AI, боя/победы.
- Будущий CampaignRun содержит session и строгий control, но не меняет CampaignSession. Авторизованные wrappers проверяют полную схему, request/command, stale, active и контроллер до вызова прежних исполнителей. Ручные red-команды в AI-режиме запрещены независимо от кнопок.
- Один отменяемый ticket после успешного человеческого blue-endTurn либо явного Resume-confirm на red. Ticket захватывает identity/generation/source/turn, потребляется до синхронного пакета; успех принимает run атомарно и возвращает blue. Второй red-endTurn не нужен: первый уже внутри AI-пакета.
- Ошибка не повторяется и не откатывает предыдущий blue-endTurn. Save/load/new/menu/takeover отменяют scheduled до pending/IO; cancel и failure не возобновляют. Red после load всегда paused. Подтверждённый takeover меняет только control на local без игрового хода.
- В AI-режиме наблюдение фиксировано blue; red-summary/финансы/разведки не передаются панели. Только нейтральное завершение/ошибка. Local сохраняет прежний помощник обеих сторон.
- Будущий save2/1: обязательный control, policy ID expansion-v1 для AI, тот же ключ слота. Новый run-кодек/менеджер принимает строго1/1 с явной миграцией в local без записи, либо2/1 с проверкой control/policy. Старый state-only API остаётся только1/1, не должен терять control нового документа. Формат2 **ещё не включён**.
- Зафиксированы отказ неизвестных policy/rules, byte cap, сохранность full snapshots/счётчиков/маршрутов, отсутствие таймеров/summary/pending в save, матрица будущих pure/scheduler/UI/persistence-тестов.

Согласованы [README](../../README.md), [CAMPAIGN](../../docs/CAMPAIGN.md), [AI](../../docs/CAMPAIGN_AI.md), [SAVE](../../docs/CAMPAIGN_SAVE.md), план. Удалены устаревшие формулировки о незавершённом cleanup S3.29: завершение подтверждено существующим [отчётом04](04-campaign-ai-ui.md), а не новым браузерным прогоном.

При сверке отклонены противоречащие исходникам варианты: добавлять control в строгий формат1 без смены версии; требовать второй ручной red-endTurn после AI; отвергать допустимые cap/terminal snapshots при загрузке; считать отсутствие будущих API в текущем коде ошибкой проектного этапа. Описанное отсутствие реализации намеренно, интеграция отложена.
